# 分けても、まだ何も分からない

秘密を n 個に分けて配る。足せば戻る。それだけなら暗号ではない。n-1 個を持っていても何も分からないことを、証拠で示す。

Week 2 の mechanism 問題。 加法的秘密分散を F_p 上で実装する。 足し算で戻ることは数行で書けるので、 checkpoint はそこではなく「n-1 個では何も分からない」という性質を実行可能な形で示させることに置く。

hides-the-secret checkpoint は participant の complete_shares を field の全要素に対して回す。 同じ n-1 個の share から、 どの秘密に対しても辻褄の合う最後の 1 個を作れるなら、 その n-1 個は秘密について 何の証拠でもない。 これが「漏れない」の実行可能な定義になる。

threshold checkpoint は必要数を答えるだけでは通らない。 同じ n-1 個と両立する相異なる 2 つの秘密を 提出させる。 数を当てるのは推測でできるが、 2 つの証人は理解がないと作れない。

hidden test は starter の自明な分割 (party 0 に秘密をそのまま渡す) を明示的に落とす。 round trip だけを見る test はこれを通してしまい、 それは分散になっていない。

Week 2 の教材は pinned commit 時点で未公開のため courseAlignment.sources は持たない (schema は この場合のために sources を任意にしている)。 #219 が公開を検出した時点で対応づけを確定する。 status は draft のままにする。

## ブラウザでの進め方

1. Participant Portal で問題を起動し、**Browser Workbench** を開く。
2. `inspect` で deploy 固有の fixture と公開された証拠を読む。
3. 画面内の starter を編集し、`test` で公開テストを実行する。
4. 表示された直接回答欄を、inspect と実験結果から埋める。
5. `prepare` で全 checkpoint の提出値を作り、Portal へ貼る。

直接回答は `prepare` により現在の deploy seed へ結び付けられます。

## 学習目標

- 加法的秘密分散を有限体上で実装できる
- 全 share を集めたときだけ秘密が戻ることを確認できる
- n-1 個の share が秘密について何の情報も持たないことを実際に示せる
- 自明な分割が分散になっていない理由を説明できる
- 秘密を変えずに share を入れ替えられる

## Checkpoint

| Checkpoint | 内容 | Points |
| --- | --- | ---: |
| `share-and-reconstruct` | 分けて、集めて、戻す | 50 |
| `hides-the-secret` | 足りない集合からは何も言えないことを示す | 45 |
| `threshold` | 必要数を、証人つきで答える | 45 |
| `rerandomize` | 秘密を変えずに share を入れ替える | 30 |
| `transfer` | 見たことのない設定でも成立させる | 30 |

## 解説

## 足せば戻ることは、まだ何でもない

加法的秘密分散の算術は数行で終わる。 価値があるのは「n-1 個では秘密について何も分からない」ほうで、 これは主張ではなく示すものだ。

## 「漏れない」の実行可能な定義

同じ n-1 個の share から、 field のどの秘密に対しても辻褄の合う 最後の 1 個を作れるなら、 その n-1 個は秘密の証拠になっていない。 complete_shares が全要素で成功する ことがそのまま証明になる。 これが Week 6 の over-opening (途中で share を開けてしまう) を 「なぜまずいか」で語れるようになる土台になる。

## 自明な分割は分散ではない

party 0 に秘密をそのまま渡し、 残りを 0 にすれば足し算は合う。 round trip test は通る。 だが party 0 は最初から全部知っている。 hidden test がこれを明示的に落とすのは、 「テストが通る」と「性質が成り立つ」の差がこの問題でも同じ形で現れるからだ。

## rerandomize

和が 0 になる offset を足すと、 秘密は変わらないまま share は全部動く。 実プロトコルでは、 同じ share 集合がラウンドを跨いで結び付けられないようにするために使う。 固定の期待値ではなく「秘密が保たれ、 かつ全要素が動いた」という関係で検査している。
