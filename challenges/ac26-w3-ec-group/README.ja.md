# (0, 0) は無限遠点ではない

有限体上の楕円曲線の点が群をなすことを、例外ケースまで含めて実装で確かめる。toy 曲線の多くは (0, 0) を含むので、それを単位元に流用する実装は本物の点と単位元を区別できなくなる。

Week 3 の 2 問目。 前問で作った体の上に楕円曲線の群を組み、 point addition・doubling・scalar multiplication を例外ケースまで含めて実装する。

本問題の toy 曲線は 7 つ中 6 つが b = 0 であり、 したがって **(0, 0) が曲線上の実在の点** (位数 2) である。 単位元を (0, 0) で代用する実装は、 この点と単位元を区別できなくなる。 misconception-infinity-is-zero-coordinate が仮定の話ではなく、 その場で観測できる欠陥になるよう曲線を選んである。 fixture 生成側は 「判別式が 0 でない」 と 「y = 0 の点が存在する」 の両方を満たす曲線だけを持つ (後者は垂直接線の分岐が到達可能であるために必要で、 満たさない候補は候補から外した)。

曲線が小さい (点の数が 23〜47 程度) ため、 hidden test は標本ではなく全数を回す。 on-curve は p^2 通りの座標対すべてを分類し、 addition は相異なる点の全順序対、 doubling は全点、 group axioms は群全体で検査する。 「一般式は合っているが単位元 / P+(-P) / y=0 で壊れる」 実装に隠れる場所が無い。

trace checkpoint は各 step の accumulator が 「そこまでに消費した下位ビット × P」 に一致することを検査する。 ビット順を逆にする実装はここで落ちる。

最後の checkpoint は secp256k1。 公開されている標準パラメータ上で同じ抽象がそのまま動くことを見る。 検査する関係は 「どこかから写した値と一致するか」 ではなく、 パラメータの定義から従うもの (G が曲線上にある、 n*G = O、 (n-1)*G = -G、 (k+m)G = kG + mG) だけにしてある。

constant-time 性や side-channel 耐性は主張しない。 double-and-add の trace はビットに依存して分岐し、 それ自体が実鍵では side-channel になる。

## 解説

## なぜ (0, 0) を単位元に使えないのか

この問題の toy 曲線は多くが b = 0 で、 その場合 (0, 0) は y^2 = x^3 + ax を満たす。 つまり曲線上の実在の点であり、 しかも y = 0 なので位数 2 の点である。 単位元をこの座標で代用すると、 その点と単位元が区別できなくなる。

「無限遠点だから (0,0) でいいだろう」 は、 曲線を選べば本当に壊れる。 hidden test は (0, 0) が曲線上にある設定で、 それが単位元と等しくないことを名指しで検査する。

## 4 つの場合分け

加算は 1 つの式ではない。

1. どちらかが単位元 → もう一方を返す
2. x が同じで y が符号反転 → 単位元 (y = 0 の点の doubling を含む)
3. 同じ点 → 接線の傾き (3x^2 + a) / 2y
4. それ以外 → 弦の傾き (y2 - y1) / (x2 - x1)

3 を 4 の特殊ケースとして書くと、 分子も分母も 0 になって割れない。 doubling が別式なのは効率のためではなく、 弦が定義できないからである。

## 全数検査

曲線が小さいので、 検査は標本ではなく全数で行う。 on-curve は p^2 通りの座標対すべて、 addition は相異なる点の全順序対、 doubling は全点、 group axioms は群全体。 一般ケースだけ合っている実装が隠れる場所は無い。

## trace がビット順を捕まえる仕組み

double-and-add は下位ビットから消費する。 step i の直後、 accumulator は 「下位 i+1 ビットが表す数 × P」 でなければならない。 trace checkpoint はこれを各行で検査するので、 上位ビットから消費する実装は最初の行で落ちる。 「最終結果だけ合っていればよい」 では通らない。

## secp256k1 で何を検査しているか

最後の checkpoint は公開標準パラメータ上で同じ抽象を動かす。 検査する関係は、 どこかから写した期待値との一致ではなく、 パラメータの定義から従うものだけにしてある。

- G が曲線上にある
- n は群の位数なので n*G = O
- したがって (n-1)*G = -G、 (n+1)*G = G
- (k+m)G = kG + mG

写した値が 1 つも要らないので、 転記ミスや出所不明の定数が混入する余地が無い。

## constant-time ではない

double-and-add はビットに依存して分岐し、 加算の回数がビットの立ち方で変わる。 実鍵に対しては、 その性質そのものが side-channel になる。 ここでの目的はアルゴリズムを読めるようにすることであり、 production 実装の手本ではない。
