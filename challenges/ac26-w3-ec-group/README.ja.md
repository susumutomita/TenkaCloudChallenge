# (0, 0) は無限遠点ではない

> Advanced Cryptography Program 2026の非公式・独立した補助教材です。講座運営者による提供・公認ではありません。

## 前提 — 署名に使う「点の計算」を修理する

あなたは署名プログラムの計算担当です。`curve.py` は点を足しても元の点を返す未完成の状態。**「起動」→ 問題エディタ →「証拠を確認」**で自分の曲線を見て、まず点が曲線上かを判定します。「公開テストを実行」で確認し、小問の提出ボタンで採点します。

**楕円曲線**は、ここでは `y² = x³ + a*x + b` を、素数pで割った余りで満たす座標(x,y)の集まりです。p・a・bが曲線の設定です。pは3より大きく、`(4*a**3+27*b**2)%p != 0` を満たす設定が渡されます。この条件は点の足し算を定めるためのものです。

点Gをk回足した点をQ=kGと書きます。これが後の署名の計算の土台です。**小さな練習用曲線では、kを順に試して逆算できます。** 適切な大きな曲線では逆算が難しいと考えられています。この問題で署名やゼロ知識証明そのものを作るわけではありません。

## 数と点の約束

| 名前 | 意味 |
|---|---|
| 法p / mod p / `%p` | pで割った余りを使うこと。負の数も0以上p未満へ直す |
| 数の逆元 | 掛けて余り1になる相手。7で割るなら6の逆元は6（6×6=35+1） |
| O（無限遠点・単位元） | 足しても相手を変えない特別な点。P+O=P。座標は両方None |
| −P（点の逆元） | Pと足すとOになる点。(x,(-y)%p)。−O=O |
| 群 | 足した結果も中に残る・単位元がある・逆元がある・括弧を変えても同じ、を満たす集まり |
| 位数 | 点ならOへ戻る最小の正の回数。群ならOを含む点の個数 |
| ビット | 二進表記の一桁（0か1）。2で割った余りを繰り返し読むと下の桁から得られる |
| checkpoint | 独立に採点される小問。ここでは8問 |

この点の足し算では、括弧だけでなく順番も交換できます。異なる曲線の点は混ぜません。同じ(p,a,b)で作った別のCurveは同じ曲線です。点の等価性とhash（Pythonが値を辞書などに格納するとき使う整数）も曲線の設定と座標で決めます。等しい点のhashは同じにします。

**割り算の作り方**：分母dを余りに直し、掛けて余り1になる数uを使います。分子vなら `(v*u)%p`。Pythonの `pow(d,-1,p)` はこのuを計算する組み込み関数です。大きなpでも候補を1個ずつ探しません。dが0のときは使えないので、以下の例外を先に分けます。逆元を作るアルゴリズム自体は前の `field-inverse` で扱います。

## Oと(0,0)を分ける

7で割った余りを使う `y²=x³+x` では、(0,0)も式を満たす普通の点です。Oの代わりに使えません。

```text
P=(1,3) → 2P=(0,0) → 4P=O
普通の点    普通の点     (None,None)
```

## 点を足す 4 通り(座標を足すのではない)

曲線 `y² = x³ + ax + b (mod p)` の 2 点に第 3 の点を対応させる決まりを「足し算」と **呼ぶことにします**。使う公式はこれだけ(導き方は要りません)。違う 2 点なら **λ = (y₂ − y₁) ÷ (x₂ − x₁)**、同じ点(2 倍)なら **λ = (3x₁² + a) ÷ (2y₁)**、どちらも **x₃ = λ² − x₁ − x₂、y₃ = λ(x₁ − x₃) − y₁**。例外は、x₁ = x₂ かつ `(y₁+y₂)%p=0` のとき和は **O**。

紙で1回：7で割る曲線 `y²=x³+x` の P=(1,3) を2倍します。分子は `3×1²+1=4`、分母は `2×3=6`。6の逆元は6なので、λは `4×6` を7で割った余り3です。x₃は `3²−1−1=7` の余り0、y₃は `3×(1−0)−3=0`。したがって **2P=(0,0)**。もう一度2倍すると y=0 の例外で **4P=O** です。

## 最初の一手

Participant Portal で **「起動」** を押すと、同じ画面に **問題エディタ**(`curve.py`)が出ます。

**「証拠を確認」** を押すと 5 つ出ます。①health token(提出しない)②この環境の曲線(p・a・b)③曲線上の点の個数(O を含む群の大きさ)と y = 0 の点の一覧 ④点の最初の 8 個((0, 0) があれば注意書きも)⑤k = 13 の下ごしらえ(13 を 2 進、下の位からのビット `[1, 0, 1, 1]`、ステップ 4、trace 1 行の形。値そのものは出ません)。

**紙で**(提出欄なし): 曲線の式に x = 0, y = 0 を入れ、(0, 0) が曲線上かを確かめる。あるなら上の手順で 2 倍すると何になるかも。Oと座標を持つ点を区別してから、コードへ進みます。

## 答えるもの — checkpoint は 8 つ

書き換えるのは `curve.py` だけ。エラー名 `NotOnCurve`・`CurveMismatch`、`Point`・`Curve` のクラス枠、`double_and_add_trace` の枠は入っています。

**約束**(starter のとおり):

- `Curve(p, a, b)`。`Curve.contains(点)` は曲線上かを True/False で返し、**OにはTrue**。`Curve.point(x, y)` は点を作り、曲線上でなければ `NotOnCurve`。`Curve.infinity()` は O。
- **O は x・y とも `None` の `Point`**。(0, 0) は本物の点なので使えない。`Point.is_infinity` が True なのは O のときだけ。
- 返す点の x・y は毎回 0 以上 p 未満に。`-P`(`__neg__`)は (x, −y mod p)、`-O` は O。
- `P + Q`(`__add__`)は上の 4 通り。違う曲線の点どうしは `CurveMismatch`。
- `P.scalar_mul(k)`(`k * P` や `P * k` でも)は P を k 個足したもの。k = 0 は O、k が負なら `-P` を |k| 倍。**double-and-add** で書く(k を 2 進で下の位から見て、ビットが 1 なら足し、毎回「足す相手」を 2 倍)。1 個ずつ足すと secp256k1 の256ビットの数が終わりません。
- `double_and_add_trace(point, scalar)` は0以上の整数scalarが対象です。0なら空リスト。正なら1ビット1行です。負の回数はscalar_mulで扱います。indexは0から始まる整数、bitも整数、addedとon_curveはTrue/Falseです。行数はscalarの2進の桁数で、**下の位から**。1 行は `{"index", "bit", "accumulator_before", "addend_before", "added", "accumulator_after", "addend_after", "on_curve"}`(点は O なら文字列 `"O"`、それ以外は `"(x, y)"`)。accumulatorはここまで足した点、addendは今回足す候補の点です。beforeは操作前、afterは操作後。ステップiの直後、`accumulator_after` は「k の下から i+1 桁が表す数 × P」、`addend_after` は「2^(i+1) × P」、`on_curve` は True。k=5(2進101、下から `[1,0,1]`)なら3行です。`accumulator_after` は1P→1P→5P、`addend_after` は2P→4P→8P、`added` はTrue→False→True。

| 小問 | 直す場所 | 確かめる動き |
|---|---|---|
| on-curve (30点) | contains / point | 式を満たす点を受け入れ、違う点をNotOnCurveで断る |
| identity (30点) | infinity / is_infinity / __neg__ | P+O=P、P+(−P)=O。(0,0)をOにしない |
| add (45点) | __add__ | 違う2点に公式を使う |
| double (45点) | __add__ | 同じ点を2倍。y=0ならO |
| scalar (45点) | scalar_mul / __mul__ / __rmul__ | 0倍・負の回数も含め、2倍と足し算を組み合わせる |
| trace (35点) | double_and_add_trace | 各桁の前後を記録する。0なら空リスト |
| properties (40点) | 上の操作の組合せ | 括弧・順番・同じ設定の別Curveを使っても結果が一致する |
| secp256k1 (30点) | 同じコード | 大きな数の設定でも計算が完了する |

各 checkpoint の **「提出 (+N pt)」** を押すと、そのときの `curve.py` が送られて採点(打ち込む欄なし)。8 つは独立採点、まちがえるごとに −15 点。**「公開テストを実行」** は、小さい点の所属・O・足し算・2倍・k倍・計算過程・曲線の比較・画面の点を確認します。未公開の設定や256ビットの計算すべてを保証するものではありません。**「初期状態に戻す」** で元の `curve.py` に戻ります。

## ここで作った足し算に、署名がそのまま乗る

例外まで含めて足し算を作り、見たことのない曲線でも群の決まりが成り立ち、256 ビットの実パラメータでも動いたら終わりです。この足し算と k 倍が、次からの署名(`ac26-w3-schnorr` 以降)の土台。なお、ここで書く trace はビットの値で処理が分かれます。本物の鍵ではその分かれ方自体が漏れの手がかりになるので、これは学習用で、そのまま真似する手本ではありません。




## 作問者向け：実行環境と検証

参加者用イメージにはエディター、スターター、小さな公開例、制限付きの値取得アダプターを入れます。ホストへ公開しない検証サービスがパラメーターの生成と独立した点の検査を持ちます。両サービスは非root、init、読み取り専用ファイルシステム、メモリー・プロセス制限、権限削減を使います。ホストのループバックへポートを公開するのはWorkbenchだけです。参加者用イメージに非公開チェッカー、生成用コード、参照解答は入れません。

提出コードはシードやチェッカーを持たない新しいworkerで実行します。親が曲線の設定、正規化した座標、型、演算結果を検査し、採点結果を決めます。ネイティブCPythonアダプターがPythonフレームの外で実際に返された例外を観測し、応答を生成します。このアダプターには点の足し算の解法を入れていません。コンパイラーはDockerのビルド段階だけです。独自の通信形式で値を返す提出も数学的検査を満たす必要がありますが、その場合にPythonの戻り値の由来を認証するものではありません。

既存の計算時間30秒を維持し、HTTP本文の受信15秒とは分離します。検証サービスへの転送待ちは35秒です。workerはアドレス空間512 MiB、64プロセス、応答1件と結果以外の出力累計64 KiBに制限します。Linuxの制限で新たなファイル・ネットワークアクセス、永続的なプロセス間通信、監視プロセスの変更を禁止し、実行後にworkerのプロセスグループを終了します。ローカルDockerの所有者から内部を隠す仕組みではありません。

```sh
make test                    # 編集したスターターの公開例を確認
make test-one ID=trace        # 名前が一致する公開例だけを確認
make inspect K=5             # 自分の設定と計算過程の形を見る
make reference-test          # 作問者用の参照解答と10種類の誤実装
make runtime-test            # 作問者用のLinux実行境界の回帰テスト
make verifier-down           # このローカルCompose環境を削除
```

カタログのルートでは`make install`と`make agent-gate`を実行します。読者役の作成経緯と検証結果は`local/tests/hidden/READER.md`に記録します。途中のテスト成功を、最終版のPortal導線の確認済みとは扱いません。

ローカルではAWSリソースを作りません。DockerのCPU・メモリー・ディスクとコンテナーは停止まで資源を使います。プラットフォーム上の費用は選んだTenkaCloudの構成とイベント期間に依存し、ここでは金額を推定しません。デプロイした場合はプラットフォームの停止・削除操作で終了します。このローカル検証はAWS実機確認や実用暗号としての安全性を主張しません。
