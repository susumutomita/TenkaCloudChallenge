## 物語

前の問題は 1 つのメッセージを 1 つの環の上に置き、どこまで押せるかを計算させました。
この問題では、それを実際に運ぶ 2 つの構成を作ります。2 つは同じ構成です。

```text
LWE     secret s は n 個の小さい整数のベクトル
        b = <a, s> + encode(m) + e                    (mod q)

RLWE    secret s は N 係数の多項式
        b = a*s   + encode(m) + e                     in R_q
```

1 行目のスカラーを全部多項式に置き換えると 2 行目になります。内積が多項式積に、
1 個のメッセージが N 個に、1 個の noise が N 個に変わります。秘密が消えたあとに残るもの、
すなわち **phase** はどちらも `encode(m) + e` で、それを復号する規則は前の問題のまま変わりません。

なのでその規則は配ってあります。`encode`・`decode`・`centered`・`noise_interval` は
starter の冒頭に実装済みで入っています。採点対象はその下だけです。

環は `R_q = Z_q[X] / (X^N + 1)` です。**プラス**であることに注意してください。
`X^N = -1` なので、環の上端を越えた係数は符号を反転して戻ってきます。

## 本当に難しいのは 4 つ

| | なぜ効くか |
|---|---|
| **折り返しの符号** | 閾値ではなく周期。次数 N は符号を反転して次数 0 に戻り、次数 **2N** は符号が戻って正になる。環の元同士の積が届く最大次数は 2N-2 なので、そこには決して届かない —— 暗号化と復号をいくら回しても、どちらの規則を書いたかは判明しない。 |
| **phase は引き算** | `b + <a, s>` は well-defined な数で、`<a, s>` が scaling の倍数のときは正しいメッセージに復号される。1 例から書いたテストを通すには十分な頻度で起きる。 |
| **N 係数、N 予算** | RLWE の各係数は自分のメッセージを運び、丸め境界までの距離を自分で使う。決めるのは最悪の 1 係数。合計でも平均でも大きさでもない。 |
| **secret は ternary** | 係数は `{-1, 0, 1}` で、本当に負になる。Python の `%` に特別扱いは要らないが、剰余が飾りではなく仕事をしているという意味ではある。 |

## cyclic は「間違った答え」ではなく「別の環」

添字を `% N` で畳むと `X^N = +1` の環になります。これは壊れた実装ではなく、
別の well-defined な環での正しい積です。だからこそ大量のサンプルで正しく復号され、
round-trip テストは一度も気づきません。

反例は 1 つで決まります。`X^(N-1) * X` は -1 か、+1 か。
議論より反例が安いので、`make inspect` が両方を並べて印字します。

## 「長いベクトルの LWE」より強い主張

積の係数 k は `sum_j v[j] * s[j]` と書けます。v は mask から作られるベクトルで、
相手は k によらず同じ secret です。つまり 1 本の RLWE 暗号文は、
**同じ mask を共有する** N 本の LWE 型の式であって、独立な N サンプルではありません。

v の成分は mask の並べ替えで、係数 k に届くために次数 N を跨いできた成分だけ符号が反転しています。
そのマイナスを落とすと mask の巡回シフトになります —— 実在するベクトルで、実在する等式を満たしますが、
環が違います。これが `correspondence` checkpoint です。

この係数ベクトルは、問題 550 で sample extraction が RLWE 暗号文から実際の LWE 暗号文を
取り出すときの土台にもなります。ここで採点するのはベクトルの形だけで、
取り出しと key switching はそちらの問題です。

## 遊び方

```bash
make inspect            # 環、LWE サンプル、RLWE サンプル、そして 2 つの積の規則
make inspect SECRET=1   # 同じものを、secret も表示して
make test               # public test
make reset              # starter/ を元に戻す
```

編集するファイルは `local/starter/lattice.py` の 1 つだけです。

`make inspect` は既定で secret を伏せます。一度伏せたまま読んで、
phase が実際にどの量に依存しているかを確かめてください。これは toy で secret は総当たりできる長さなので、
これは読み方の規律であって、境界ではありません。

## 採点

8 つの checkpoint を独立に採点します。誤答は 1 回 10 点。

| Checkpoint | 配点 | 検査内容 |
|---|---:|---|
| `normalize` | 25 | 任意長・負係数の列、次数 N・2N・3N での折り返し |
| `ring` | 25 | 加算・減算・negacyclic 積、`X^(N-1)·X = -1`、分配法則 |
| `lwe` | 25 | 暗号文、phase、往復、そして noise 予算の両端 |
| `rlwe` | 25 | 同じことを環の上で、N 個のメッセージすべてが戻ること |
| `correspondence` | 25 | 任意の secret に対し `<v, s>` が積の係数 k に一致すること |
| `boundary` | 25 | 最悪係数で決まる生存判定、最初に失敗する標本、空の列 |
| `transfer` | 25 | 見たことのない seed 由来の環・次元・secret で上記すべて |
| `validate` | 25 | 成立しない 13 個を reject し、正当な 4 個を通す |

8 つのうち 4 つに hint があり、いずれもその checkpoint の 50% 上限の内側です。

## equivalent mutant について

mutation の候補のうち 2 つは、生き残らせるのではなく**外しました**。どちらも議論ではなく検証で確認しています。

- `phase_coefficient_terms` の折り返し添字を `-mask[(k + N - j) % N]` に変えても、
  どの出力も変わりません。その分岐が走るのは `j > k` のときだけで、そのとき `k + N - j` は
  すでに `[k+1, N-1]` に入っています。到達しうる全入力で剰余は no-op です。
- 同じ式の外側の `% q` を落とすことも、符号を反転しない側の分岐では観測できません。
  mask は 1 行上で正規化済みだからです。観測できるのは符号の方なので、mutation はそちらを壊します。

殺せない mutation を一覧に残すと `SURVIVED` の行を無視してよいと教えることになるので、どちらも残していません。

## これは安全ではないし、安全なふりもしない

`q` は手で全列挙できる大きさ、secret は総当たりできる長さです。
`make inspect` が中間値を全部印字できるのはそのおかげだけです。
実運用のパラメータは格子問題の裏に secret を隠しますが、これは何の裏にも隠していません。
toy の正しさと production の安全性は別の主張で、この問題は前者しか主張しません。

## 保証範囲

ローカル実行は**自習用の honor-system 検証**です。マシンも Docker デーモンも image も
あなたの管理下にあるので、image の中身はあなたに対して秘匿されていません。
`reference/` と `tests/hidden/` を bind-mount しないのは、あなたの git checkout に
紛れ込ませないためであって、手が届かなくするためではありません。

verifier が実際に保証するのはもっと狭く、そして本物です。提出コードは verifier を
ハングさせたりクラッシュさせたりできません。checkpoint は echo した id しか加点できません。
結果は期待値を漏らしません。fixture はこのデプロイの seed 由来なので、暗記した答えは持ち越せません。

これは自習と誠実な練習を支えます。競技順位・試験・修了判定は**支えません**。
それらには participant が管理しない verifier が必要で、
[#271](https://github.com/susumutomita/TenkaCloudChallenge/issues/271) で追跡しています。
