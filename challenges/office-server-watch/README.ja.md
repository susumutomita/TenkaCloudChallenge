# サーバーの見張り役 — CloudWatch入門

4人チーム向け、difficulty 1・100点の追加AWS Challengeです。初回イベントのEC2準備Gateと復旧Battleとは独立して選べます。初心者向け60分の回へ追加問題をすべて詰め込まないでください。

## 参加者の流れ

用意されたEC2のCPUを選ぶ → 指定名でアラーム設定 → 設定成功と実際の発報確認を区別。

ポータルのAWS Console接続を使い、GameUrlを開きます。ミッションごとに操作担当を交代し、残りの3人は図を読む・次の一手を説明する・結果を確認する役です。確認と3段階ヒントは無料。最後の合言葉だけを採点し、正解100点、誤ったポータル提出は5点減点。途中で加点してGateが早く開くことはありません。

## 構成と権限

t3.micro EC2 1台と8 GiB gp3、専用VPC・サブネット・セキュリティグループ、参加者が作るCPUアラーム1個、検査・撤収用Lambdaと保存1日のログ。公開IPv4・IGW・NAT Gateway・SNS購読は不要です。

[共有ランタイム](../../runtimes/aws-intro/README.md)をそのまま問題のtemplate.yamlに埋め込みます。操作は指定リソースに限定し、検査Lambdaの環境変数・採点秘密・任意ロール・他チームのデータ変更は許可しません。参加者ロールはExternalId必須。リソース単位の制限ができない一覧APIでは同じアカウント内の一覧が見える場合があるため、競技者アカウントの分離を推奨します。参加者はスタックを再デプロイできません。

DescribeAlarmsでInstanceId・CPUUtilization・平均・300秒・80より大きい・評価1回を照合。通知や復旧アクションは対象外で、IAMでもアクション指定を禁止します。初期のデータ不足は不合格にしません。実負荷による発報やメール受信は未確認です。

進捗は問題とデプロイごとに署名します。GameUrlと引き継ぎコードはチーム内だけで共有します。最終合言葉は宣言済みの採点Outputで、プラットフォームが表示から除外します。NoEchoはOutputsを隠さないため、参加者へCloudFormationのOutput読み取りを許可しません。

## 費用と撤収

標準リハーサル地域はap-northeast-1。この追加問題に10〜15分と、デプロイ・AWS観測の待ち時間を見込みます。AWS利用料は開催者負担で、無料は保証しません。上記リソース、APIリクエスト、Lambda、ログ、データ転送が費用対象です。カスタマー管理KMSキー・追加インデックス・プロビジョンド容量・EC2詳細監視・通知は使いません。権限は対象名を制限しますがアカウント全体の支出上限ではないため、運営者が利用状況も確認します。

終了後はプラットフォームから削除します。CloudFormation管理リソースに加え、参加者作成のテーブル・キュー・アラームがある問題は専用Lambdaが指定名だけを削除。DynamoDBは削除完了を待ちます。Lambdaのみの問題にデータ撤収Hookは不要です。スタックの削除完了と残存リソースを確認してください。取り残しは課金が続きます。

## ローカル検証

```sh
make build
make test
python3 -m unittest discover -s ../../runtimes/aws-intro/tests -v
python3 preview.py --port 5685
```

SDK契約テストには共有ランタイムのrequirements-test.txtを使います。プレビューはテストデータであることを表示し、AWSを操作しません。テストはデプロイされるハンドラ、正常・異常のAWS観測、最後だけの採点、撤収範囲を検証します。実AWSへのデプロイ・コンソール権限・反映時間・費用・撤収は任意の開催前リハーサルで、この変更では未実施です。
