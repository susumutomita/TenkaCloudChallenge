# はじめての開催責任者

来月のイベントを任された運営者として、人数と協力者から準備を計画し、開始の判断、得点の問い合わせ、未完了の撤収の引き継ぎを行います。[LPの開催ランブック](https://tenkacloud.com/docs/operate/run-an-event/)を4場面で体験する問題です。

## 参加者の進め方

Webを開き、場面の条件から計画・判断を入力して「確認する」を押します。条件を満たすと確認票が出ます。ポータルの対応するチェックポイント（plan、rehearsal、incident、closeout）へコピーして提出してください。各25点、合計100点。誤った確認票の提出は順に2/1/1/1点減点です。練習画面での間違いは得点に影響しません。各3段階のヒントは0/2/3点で、必要な方法と条件は無料の画面にあります。

日本語・英語に対応しています。終了後はリンク先の企画表を主催者の管理場所へコピーし、実際の人数・会場・担当へ置き換えます。この問題は会場予約、協力者への連絡、AWS起動、本番準備の認定を行いません。

## 構成と採点

非rootのNodeコンテナ1個で、Webは8080、別の検証口は8081を使います。ホストへの公開は両方ともループバック限定です。既存のmulti-verify形式 `{checkpointId, submission}` で判定し、点数はプラットフォームが管理します。確認票は注入された実行ごとのFLAG_SEEDと場面の確認結果から発行します。秘密や確認票を静的ファイルとして配布しません。場面は順に進みます。競技全時間を担当できれば複数の協力者を正解として扱います。

再読み込み後は各場面を再確認して確認票を取得できます。コンテナ再起動で練習の進行は初期化されます。記録済みのポータル得点はプラットフォーム側の状態です。

ローカルDocker専用でAWS資源は作りません。AWSデプロイ用の問題ピッカーには表示されません。プラットフォームへの専用機能追加はありません。

## ローカル確認と終了

このディレクトリで `make test`（Node 24）を実行します。人数の変化、担当者の複数解、前段の条件、開始・問い合わせ・撤収の判断、確認票、HTTP提出形式を検査します。テストと参照判断はDockerビルド対象外です。

TenkaCloud既存のローカル起動手順でevent-host-rehearsalを選ぶとFLAG_SEEDが注入されます。単独確認は新しい秘密を環境変数へ設定し、`docker compose -f local/docker-compose.yml up --build` を使います。秘密の公開や外部へのポート公開はしません。終了は同じComposeの `down`。状態はメモリ内のみでクラウドの撤収は不要です。

ブラウザ・ランタイムの検証記録はVALIDATION.mdに記載します。実会場、実参加者、クラウド環境、費用確認は運営者が開催前に行う別のリハーサルです。
