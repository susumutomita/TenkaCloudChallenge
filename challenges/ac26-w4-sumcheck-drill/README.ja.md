# 合計のごまかしを、短い式で見つける

> Advanced Cryptography Program 2026 に対応する非公式・独立教材です。
> 提携・公認ではありません。お問い合わせは TenkaCloud へ。

Week 4 / 順序405 / 難易度3 / 200点 / draft / 目安40〜60分。

5か7で割った余りを使い、小さな計算を点検します。SumCheckの二つの式を追い、
最後に偽の式を作って、式を固定してから確認する場所を選ぶ理由を確かめます。
見える普通の数を使う演習です。

## 参加者の進め方

1. 「起動」→「証拠を確認」。`sumcheck_drill.py` の最初の `return None` を
   `return layer(p,x)` に替えて公開テストを実行し、`circuit ->` の値を提出します。
2. 次の五関数を無料の対応コードで埋めます。各関数に必要な引数と補助関数がそろっています。
   公開テストは見本と照合した後、自分の数での出力を表示します。他の未記入の欄があっても提出できます。
3. 先に教えられたr2に合う偽の式を作ります。次は、見逃し点がちょうど2点ずつで重ならない二式を
   作ります。公開された条件を満たす別解も受理します。

| 回答欄 | 返す値 | 点数 |
| --- | --- | ---: |
| circuit | 足し算の答え、掛け算の答え、合計 | 20 |
| mle | 直線の位置0,1,2での値 | 15 |
| grid | (0,0),(0,1),(1,0),(1,1)での値 | 15 |
| round1 | 最初の式の二点の和、r1での値 | 20 |
| final-check | 次の式の二点の和、r2での値、自分のg(r1,r2) | 15 |
| lie | 偽の最初の二点の和、偽の次の主張 | 15 |
| lie-caught | 偽の和と先に見えたr2に合う三係数 | 50 |
| miss-points | 見逃し点の組が重ならない二つの三係数 | 50 |

必要な式と小例は全て無料です。任意ヒントは各欄「仕組み → 見本 → 自分の画面での手順」の3段。
各2点、計48点で、誤答は10点減点です。最後のヒントは有限の候補範囲と終了条件を示し、
構成する関数の完成コードは載せません。

## 数学の範囲

正直な最初の式はg(t,0)とg(t,1)の和、次の式はr1を固定したg(r1,t)です。
次数はどちらも2以下。二点の和で前の主張とつなぎ、最後は検証者自身のg(r1,r2)と照合します。

本来は式を固定してから検証者が場所を選びます。この演習で表示するのは、選別した練習用の記録です。
r1は2以上、入力は途中の値が0や同値にならない範囲で、偽の次の主張が本当と異なるため、
後半の二つの構成が可能です。プロトコル全体の無作為な抽選を再現するものではありません。
先にr2を見せる問は意図的に順序を逆にし、最後の問ではr2を渡さず全位置を調べます。
固定した各偽式が本当と一致する位置はpか所中2か所。2/pはこの最後の確認だけについての確率で、
二段のやり取り全体の安全性を表す上限ではありません。この小さい数に実用の安全性はありません。

この模型で高速化、短い証明サイズ、入力の秘匿、完全なゼロ知識証明を実証したとはしません。
手順、次数検査、最後の計算、全手順の見逃し確率については
[Thaler『Proofs, Arguments, and Zero-Knowledge』第4章](https://people.cs.georgetown.edu/jthaler/ProofsArgsAndZK.pdf)
を参照できます。

## 実行の境界

参加者イメージに入るのはスターター、公開テスト、算術補助関数、Portal編集APIです。
生成用の秘密、生成器、非公開テスト、模範解答は採点・作者用イメージだけに置きます。
参加者コードの実行前に公開情報を取得します。提出を開始回へ結び付ける識別値は認証ではありません。
非公開ポートの採点用コンテナは参加者コードを実行せず、値と構成条件を判定します。
直接回答の不正解理由は返しません。

Linux seccompで参加者コードの通信や親のメモリ・停止要求・リソース制限へのアクセスを制限し、
子にも引き継ぎます。実行後に残る子は終了します。CLIも同じ制限を使い、設定できなければ実行しません。
両サービスは非root、読み取り専用、リソース制限あり。18133番だけを127.0.0.1に公開します。
Dockerを操作できる人は自分のイメージを調べられ、完全な隔離を保証するものではありません。

## ローカル確認と終了

この問題のディレクトリで実行します。

```bash
make inspect
make test                  # 未記入なら失敗するのが正常
make test-one ID=circuit
make verifier-down
```

コードは標準入力でDockerへ渡すため、ホストのPythonや共有マウントは不要です。
inspect/testで残る採点用コンテナは `make verifier-down` で停止します。
クラウドのリソースやAWSリージョンは使いません。停止までローカルのCPU・メモリを使用します。

作者は `make reference-test`、リポジトリ直下で `make install` と `make agent-gate` を実行します。
参加者役の読解と実際のテスト・提出・採点の証拠は `local/tests/hidden/READER.md` に記録します。
人によるイベントリハーサルと実AWSイベントは未実施です。
