# つながるオフィスの準備 — AWS入門Challenge

[English](README.md) · [全体の企画 #884](https://github.com/susumutomita/TenkaCloudChallenge/issues/884)

異なる拠点のエンジニアが同じ会場に集まり、学びと交流のきっかけを作る準備Challengeです。4人で実際のAWSを操作し、**EC2起動 → IGW接続 → 経路設定 → Session Manager接続 → HTTP許可**の順に、仲間へWebページを届けます。ページのプログラムは配布済み。操作・図を読む・説明・結果確認の担当をミッションごとに交代します。

ポータルの「AWS Consoleを開く」でチームの権限へ接続し、GameUrlを開きます。画面には今の1題、対象のID、AWSへのリンク、小さな構成図、成功条件、無料の3段階ヒントを表示。AWSの操作確認と短い説明問題の両方を終えると次へ進みます。**全5題の最後だけ、100点の合言葉が出ます。** ポータルへの誤った提出は5点減点、画面内の確認とヒントは無料です。

## Gateと開催範囲

初回のイベントには `office-link-gate` と `office-link-battle` の2問だけを登録します。既存の進行Gateは既定OFFです。TenantAdminが有効化し、この準備問題をGate、Battleだけを解放先、policyをrequired、追加ボーナス0、チーム設定を継承にして保存。開催前に参加者画面でロックを確認してください。既存Gateは初回の加点で開くため、準備途中には採点用の合言葉を発行しません。チームの修了であり、全員の理解を自動保証するものではありません。

準備は #886、[実AWSの復旧Battle](../../battles/office-link-battle/README.ja.md) は #892、開催導線は #893 で追跡します。S3などの追加Challengeは開催者が選ぶもので、初回セットに自動追加しません。

## 構成と権限

**チームごとに別の競技用AWSアカウント**を使います。VPC・サブネット・ルートテーブル・セキュリティグループ・固定のネットワーク接続口・予約した公開IPv4・起動テンプレート・Session Manager用ロール・Lambda 2個・保存期間1日のログを作成します。参加者がテンプレートから `t3.micro` / 8 GiB `gp3` のEC2を1台起動。固定の接続口で同時に複数台起動することを制限します。

IGWは参加者が作成・接続します。検査後、演習側がこのEC2にだけ予約した公開IPを付けます。公開IPが付いたVPCからはIGWを外せないため、最初はIPの関連付けを行いません。8080番は演習の観測用、参加者が追加するのはHTTPの80番です。観測結果に秘密情報はありません。

採点根拠は、実資源のID・EC2の状態とチェック・対象サブネットの経路・実際の外向きHTTPS・チーム権限でのSession Manager接続記録と確認コマンドの印・必要な通信だけを許可したHTTP応答です。単に選択肢へ回答しただけでは進みません。

EC2一覧取得APIは資源単位の制限に対応しないため同一アカウント・リージョン内の読み取りです。変更操作は対象の資源とタグへ限定。参加者は採点関数のコード・環境変数・CloudFormation出力・任意ロールの付与・起動テンプレートの変更へアクセスできません。ExternalIdを維持し、画面アクセス・進捗署名・得点用の秘密を分離しています。引き継ぎコードは同じチームだけで共有してください。

共通実装は [`../../runtimes/aws-intro`](../../runtimes/aws-intro)。S3・Lambda・ログ・DynamoDB・SQS・CloudWatchの追加問題も同じ実装を使います。`build.py` は共通ソースとこの問題の `workshop.json` を `template.yaml` へまとめます。

## 費用と撤収

初回確認地域は東京 `ap-northeast-1`。AWSへの反映待ちと相談を含め**準備約40分**、Battleの時間は別に確保します。EC2・EBS・公開IPv4・Lambda・ログ・転送に料金が発生し得ます。NAT Gateway・RDS・Secrets Manager・顧客管理KMSキーは追加しません。公開IPv4は未使用でも料金がかかります。無料とは保証しません。

管理画面から問題デプロイを削除します。CloudFormationの後片付け処理が、公開IPの関連付け解除、固定接続口に付いたこの問題のタグ付きEC2の終了と待機、演習のIGW削除を行ってからネットワークを削除します。失敗はFAILEDとして表示されるため、ログで原因を確認して削除を再実行してください。EC2・ディスク・IPv4割当・IGW・関数・ログが残っていないことを確認。共有端末の進捗も消します。コード更新は学習状態のリセットにはなりません。新しい開催は新しいデプロイを使います。

## 確認方法

ローカルコマンドは [English README](README.md#verification)、実施記録と任意のAWSリハーサルは [VALIDATION.md](VALIDATION.md)。`make preview` はlocalhost限定で、AWS観測がテストデータであることを明示します。実AWSの権限・接続・削除・公式得点を確認した証拠にはしません。カタログルートでも `make install && make agent-gate` を実行します。

CFN lintのW2010はGameUrlと最終flagの既存出力契約に対する警告です。NoEchoで出力まで隠れるとは扱いません。参加者ロールからのCloudFormation出力取得を許可せず、ポータルの採点出力除去も開催前に確認します。
