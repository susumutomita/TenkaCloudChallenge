# 計算の記録から、不正な承認を見つける

> Advanced Cryptography Program 2026 に対応する非公式・独立教材です。
> 提携・公認ではありません。お問い合わせは TenkaCloud へ。

Week 6 / 順序635 / 難易度3 / 200点 / draft。

割引の合計が上限以下なら承認する機械を調べます。機械は足すたびに一定の数で
割った余りを保存するため、普通の合計とは違う値になることがあります。
三つの足し算を追い、不正な承認と、報告の条件不足を見つけます。
最初は「証拠を確認」にある三つの数を足すだけです。

## 参加者の進め方

1. Portalで開始し、「証拠を確認」の代入文を `python3` に貼ります。
2. 1行目の `sum(discounts)` を実行し、出た数を `exact` 欄へ提出します。
3. 全8行を順に進めます。Pythonの端末がなければPortalのエディタを使います。
   各関数の `return None` を対応する行のコード全体に置き換え、最後の式へ
   `return` を付けます。「公開テストを実行」で自分の計算結果を確認します。

必要な用語と計算方法は無料の問題文にあります。各欄の任意ヒントは
「仕組み → 一桁の計算例 → 自分の画面での手順」の3段、各2点、計48点です。
誤答は10点減点です。

| 回答欄 | 確かめること | 点数 |
| --- | --- | ---: |
| exact | 普通の合計 | 25 |
| trace | 足すたびに保存された数 | 25 |
| overflow | 今回の足し算で桁があふれたか | 25 |
| decision | 機械と普通の合計で承認が違うか | 25 |
| exploit | 本来の上限を超えているのに承認されたか | 25 |
| predicate | 条件が足りないことを示す反例 | 25 |
| tamper | 報告が再計算と一致するか | 25 |
| binding | 確認済み・依頼した番号・依頼した主張の三条件 | 25 |

## 扱う仕組みと境界

一桁の見本は m=8、discounts=[7,2,1]、limit=3 です。普通の合計は10ですが、
機械は7 → 1 → 2と保存して承認します。本番の入力は開始ごとに変わり、
mは8か16、一つの入力は最大15です。これは計算と主張の条件を学ぶモデルで、
zkVMや暗号証明の生成・検証を実装する演習ではありません。最後のカードは
確認済みか・プログラム番号・主張の照合を表し、例の入力はすべて見えます。

`FLAG_SEED` を受け取るのは採点用コンテナだけです。参加者用イメージには
スターター、公開テスト、Portal APIだけを入れ、問題生成器・模範解答・非公開
テストは入れません。提出には公開の一方向の識別値で開始回を結び付けます。
これは認証ではなく、正誤は別の採点用コンテナが判定します。

Workbenchの18165番だけを127.0.0.1へ公開します。採点用ポートは内部限定です。
両コンテナは非root、読み取り専用で、権限・メモリ・プロセス数を制限します。
ローカル演習はDockerを操作できる人から本物の秘密を守るものではありません。

## ローカル確認と終了

この問題のディレクトリで実行します。

```bash
make inspect
make test              # 未記入のスターターでは失敗するのが正常
make test-one ID=exact
make verifier-down
```

CLIは編集したスターターをDockerへ標準入力で送り、ホストのPythonや共有パスは
必要としません。inspect/test後は採点用コンテナを残すため、
最後に `make verifier-down` でコンテナとネットワークを終了します。
クラウドのリソースは作りません。停止までローカルのCPU・メモリを使用します。
演習全体の目安は30〜45分です。
