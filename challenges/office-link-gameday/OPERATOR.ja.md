# 60分で開催する「つながるオフィス」

目的は、普段話さない拠点・職種の人同士が、相談して1つの結果を作ることです。AWSスキルの試験ではありません。操作できたかだけでなく、**全員が役割を持てたか・仲間の言葉が役立ったか**を振り返ります。

## 初回の規模と用意するもの

最初は2〜4チーム、1チーム3〜4人を目安にします。対応容量の上限を検証した数字ではありません。拠点と経験を混ぜて編成し、経験者だけを操作担当に固定しません。

| 用意するもの | 数量・担当 |
| --- | --- |
| 開催責任者・司会 | 1人。開始、終了、障害時の判断を一本化 |
| 環境・問い合わせ担当 | 1人。司会と兼任するなら、障害対応中の進行を止めると決める |
| 会場または通話 | 全体1つ、チームごと1つの会話場所。音声・チャットどちらも使えるようにする |
| PCとブラウザ | 参加者1人1台を推奨。最低チーム1台＋カードを読める別端末。コマンド入力不要 |
| ポータル接続先・チームキー | チームごとに1組。チーム限定の連絡場所で配布 |
| チーム用AWS環境 | 本体の開催手順に従い、各チームに1つの登録済み競技アカウントと問題デプロイ |
| 記録シート | チームごと1枚。下の表をコピー |

費用支援の有無だけで準備完了とはしません。予算上限・利用するアカウント・請求確認担当・撤収期限を責任者が確認します。特定の団体からの支援は前提にしません。

ポータルへ誤った合言葉を出すと、難易度1の標準ルールで5点減点です。問題画面での試行は無料。司会は「コピーして同じ番号のA/B欄へ貼る」を先に実演します。

端末も交代する場合は、前の担当が操作の合言葉（A）をチーム内で渡します。新しい担当は同じGameUrlで同じミッションを開き、「別の端末で操作した仲間から、解説を引き継ぐ」へ貼ります。他チームや別ミッションの合言葉は受け付けません。同じ端末なら、そのまま操作担当だけ交代できます。

## いつまでに何をする？

以下は初回の作業量の目安です。実施後に実績へ置き換えます。

| 時期 | 担当・目安 | 完了の目印 |
| --- | --- | --- |
| 2〜4週間前 | 責任者、30分 | 交流の目的、対象者、候補日、人数、予算、会場/通話を1枚にする |
| 2週間前 | 環境担当、60〜120分 | 本体とカタログの参照先を固定し、Lite・テスト2チームを準備。経験の浅い協力者を2〜4人募集 |
| 1週間前 | 司会・環境担当・協力者、60分＋片付け30分 | 下のリハーサル判定を通し、所要時間とつまずきを記録 |
| 前日 | 責任者、30分 | 混成チーム、連絡先、司会台本、役割、欠席時の代役を確定 |
| 当日30分前 | 環境担当、30分 | 全員がログインでき、各チームのGameUrlが開く。公式競技時間はまだ開始しない |
| 終了後 | 環境担当、30分 | 結果保存、問題デプロイ削除、不要な本体撤収、残存リソースの確認 |
| 翌週 | 責任者、30分 | 振り返りを1枚にし、次回の担当と直す箇所を決める |

## デプロイと配布

1. [本体のAWS開催手順](https://github.com/susumutomita/TenkaCloud/blob/main/docs/operations/event-runbook.md)でLiteを準備する。問題カタログがこの問題を含むコミットか確認する。チームアカウント連携は既存のbootstrapを使う。
2. 管理画面でイベントとチームを作り、**つながるオフィス（office-link-gameday）**を選択してチームごとにデプロイする。公式の競技時間は40分にする。個別のカウントダウンを問題画面に追加しない。
3. 各チームへポータルURLとチームキーだけを限定共有する。ポータルへログインした参加者は問題のGameUrlを開く。AWSコンソールを操作する必要はない。
4. **最初のデプロイに使うチームはリハーサル専用にする。** リハーサルで加点したチームをそのまま本番に混ぜない。本番は別チーム/別イベントを作る。
5. GameUrlの役割カードを別画面で開き、そのURLを同じチームの読む担当へ渡す。これはポータルのログインキーではないが、チーム用の問題アクセス情報なので全体チャットへ貼らない。

## 60分の司会台本

| 開始から | 進め方・言うこと |
| --- | --- |
| 0〜5分 | 「今日は知識を競う試験ではありません。仲間の手がかりをつないで得点します」。名前・拠点・今日呼ばれたい名前を1人20秒で紹介 |
| 5〜10分 | 役割を決め、カードの開き方と合言葉の提出先を説明。全チームがGameUrlを開けたら競技開始 |
| 10〜20分 | ミッション1。読む人はコードを伝え、操作担当は宛先を選ぶ。**操作の合言葉だけ先に提出してよい**。その後、操作担当を替えて解説ミッション |
| 20〜35分 | ミッション2。読み手と確認役も交代。「誰に何を見せる？」を声に出し、共有後の結果を確認。続けて次の相談へ回答 |
| 35〜45分 | ミッション3。記録と控えの担当を分ける。復旧した中身を確認役が読み上げ、解説も提出 |
| 45〜50分 | 提出確認。進んでいるチームは役割を替え、難しかった箇所を60秒で教え合う。終了時刻は全員共通 |
| 50〜60分 | 公式スコアを確認して表彰。同点は同順位。「仲間のどの一言が役立った？」「職場なら何を確認する？」を1人ずつ話す |

時間割はペース配分であり、ミッションは途中でも切り替えられます。自動失点や自動障害はありません。解説は長い講義にせず、**直す → 30秒で説明 → 次の場面で判断**を繰り返します。選択肢の一致は採点できますが、言葉で理解したかは司会が聞いて確かめます。

3人なら読む人2人＋操作担当（確認も担当）、4人なら確認役を独立させます。会話が難しい人はチャットで伝えてよく、発言量で順位をつけません。速く終わった人には他の人の操作を奪わせず、次の説明を任せます。

## 開催を決める前のリハーサル判定

- [ ] 初参加者がコードやコマンドを入力せず、5分以内に1Aの合言葉を得た（目標。未達なら説明か導線を修正）
- [ ] 2チームで別のGameUrlが配られ、片方の合言葉では他方に加点されない
- [ ] 1Aだけ提出して15点、1Bを提出してさらに15点。操作だけで部分点が付く
- [ ] 同じ回答の再提出で二重加点されない。再読み込み後もポータルの得点が保たれる
- [ ] 6つの提出で100点となり、ポータル上部とスコアボードに反映される
- [ ] 英語、必要な端末・回線、役割カード、通話/チャットを試した
- [ ] 誤った選択から修正でき、助け舟を開いても減点されない
- [ ] 全員が少なくとも1回は操作か説明を担当できた
- [ ] 終了後の提出制限、デプロイ削除、残存確認を通した

コードのテスト合格と、この実AWS・複数人リハーサルの完了は別です。初回の効果を確認する前に「初心者全員が60分で完了」「交流が増える」と断定しません。

## 困ったとき

| 症状 | 次の一手 |
| --- | --- |
| 誰も話さない | カードを1人1枚ずつ担当させ、「見えているコード/時刻を1つ伝える」と具体的に頼む |
| 1人がすべて操作 | 次の解説は別の人が操作。詳しい人は30秒待って質問に答える役へ |
| 知識で止まる | 問題画面の無料の助け舟を使う。必要な専門知識を口頭試験にしない |
| 問題は成功、得点は0 | 合言葉がポータルの対応するA/B欄へ提出済みか確認。成功画面だけでは加点されない |
| リロードで控えが消えた | 同じ問題を再度解いて合言葉を得る。ポータルで提出済みなら重ねて提出する必要はない |
| GameUrlが開かない | 運営者が元の配布先とデプロイ状態を確認。全体チャットへURLや鍵を貼らない |
| 全チームが不調 | 司会が中断と次の案内時刻を伝える。問題画面だけの模擬点へ切り替えて正式結果と混ぜない |

## 次回へ残す1枚

| 項目 | 記録 |
| --- | --- |
| 日付・目的・形式 | 記入。氏名や鍵は公開資料へ残さない |
| 人数・チーム数・AWS経験 | 記入 |
| 初得点までの時間 / 完了したチェック数 | 計測する。未計測は未計測と書く |
| 全員が役割を担当できたか | はい/一部/いいえ＋理由 |
| 相談が生まれた場面 / 止まった場面 | 具体例を1つずつ |
| 次回直すこと・担当・期限 | 1〜3項目に絞る |
| 実際の準備・運営・撤収時間と費用 | 請求と残存確認後に記入 |

## 共同作問へ進むとき

コミュニティ開催は、まずこの入門版を通し、同じ「手がかりを分ける → 操作 → 説明」の型で身近な困りごとを1つ持ち寄ります。会場・開催日・共同作問者・レビュー担当・AWS費用担当は別々に決めます。3〜4月などの候補月だけでは確定開催として掲載しません。

標準問題と本体は公開OSSとして自社開催に使えます。設計・準備・当日運営の支援や、企業固有のシステムを題材とした非公開問題は、既存の開催支援・個別見積りの窓口へ相談できます。この入門セットの得点を、そのまま採用や社内認定の判定基準にはしません。評価用途では別途、測りたい能力・採点基準・配慮事項を設計します。
