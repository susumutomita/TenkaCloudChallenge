## 前提

あなたは、秘密を集めずに計算する道具の修理担当です。**起動 → 証拠を確認 → linear.py を編集 → 公開テストを実行**。各小問の「提出」で採点します。公開定数を全員に足してしまう箇所を、まず小さい例で直します。

**秘密計算（MPC）**は、複数の参加者が入力を互いに隠して計算する方法です。その部品の一つが**秘密分散**。秘密 x を、足すと x に戻る数に分けます。各人の持ち分を **シェア（share）**と呼びます。この問題は、そのシェアを使う足し算と定数倍です。

## 見るのは自分の行だけ

人数 n は2人以上。計算は**奇数の素数 p で割った余り**で行います。Python の `% p` は負の値も 0〜p−1 に直します。`a[i]` は i 番の人が持つ x のシェア、`b[i]` は同じ人が持つ y のシェアです。

```text
秘密 x = (a[0] + … + a[n−1]) % p
秘密 y = (b[0] + … + b[n−1]) % p
各人の計算 → 新しいシェア → 全部足すと計算結果
```

実際の各人には自分の行しか見せません。**このエディタは仕組みを調べるため全員の行を一覧にしています。** 一覧を足せば秘密も戻ります。画面そのものが秘密を隠す実演ではありません。

p=7 の例。x=4 のシェアは [5,6,0]、y=3 は [1,0,2]、全員が知っている公開定数 c=2 です。

| 人 | x のシェア a | y のシェア b | x+y：同じ行を足す | 2x：全員2倍 | x+2：0番だけ+2 |
|---|---:|---:|---:|---:|---:|
| 0 | 5 | 1 | 6 | 3 | 0 |
| 1 | 6 | 0 | 6 | 5 | 6 |
| 2 | 0 | 2 | 2 | 0 | 0 |
| 合計の余り | 4 | 3 | 0 | 1 | 6 |

x+y=7 の余り0、2x=8 の余り1、x+2=6。各列が欲しい結果に戻ります。

## 使う式と4つの関数

| 関数 | 各行で行う計算 | なぜ正しいか |
|---|---|---|
| `add_shares(a,b,p)` | `out[i]=(a[i]+b[i])%p` | 合計を並べ替えると x+y |
| `mul_constant(shares,c,p)` | `out[i]=(shares[i]*c)%p` | 分配法則で合計は c×x |
| `add_constant(shares,c,p)` | 0番にだけ c を足し、他はそのまま。全て `%p` | 合計に c が1回だけ加わる |
| `communication_rounds(operation)` | 各操作を判断し、不要なら0・必要なら1以上を返す | 自分の行で終わるか、値のやり取りが要るか |

最初の3関数は、入力と同じ長さの整数列を返します。順序を持つ数の並びで、Pythonのリスト `[0,6,0]` またはタプル `(0,6,0)` を使えます。以下の例はリストを使います。各要素は0以上p未満の整数です。入力の2リストは同じ人数・同じ人の順です。最後の関数は整数1個を返します。`True` や `False` は整数の代わりには使いません。

定数足し算の一般形は、公開の調整値 d[i] を足すことです。`u≡v (mod p)` は「u と v を p で割った余りが等しい」という意味です。

```text
out[i] = (shares[i] + d[i]) % p
(d[0] + … + d[n−1]) % p = c % p なら、合計は x+c
```

`d=[c,0,…,0]` が一番簡単です。全員が c を足すと x+n×c になり、目標との差は `(n−1)×c`。上の例では [0,1,2]、合計3となり、目標6と違います。ただし c=0 など差の余りが0のときは偶然一致します。**正しい手順は、たまたま一致する例以外でも働く必要があります。**

## 通信の境界を式で見る

**通信ラウンド**は参加者間で値をやり取りする段階です。ここで答えるのは厳密な回数ではなく、**不要なら0、必要なら1以上**。対象は、各人が自分の加法的シェアだけを持ち、追加の事前配布データを持たず、任意の入力の計算結果もシェアのまま返すモデルです。

| operation（操作名） | 計算したいもの |
|---|---|
| `add-shared` | x+y |
| `sub-shared` | x−y |
| `negate-shared` | −x（全員−1倍） |
| `add-constant` | x+c |
| `mul-constant` | cx |
| `mul-shared` | xy |
| `square-shared` | x² |
| `compare-shared` | 0〜p−1 の整数として x と y を比較 |

判断の順番は **操作名を式にする → 各人が持つ値を書き出す → 自分の行の計算を足して目標の式になるか確かめる**。足し算なら `(a0+b0)+(a1+b1)=x+y` なので、他人の行を受け取らずに計算できます。引き算や符号反転にも、同じ確かめ方を当てはめてください。

2人なら、秘密どうしの積は次の形です。

```text
(a0+a1)(b0+b1) = a0b0 + a0b1 + a1b0 + a1b1
                                  ↑ 他人のシェアと組になる交差項
```

人0は a1,b1 を、人1は a0,b0 を持っていません。手元の積だけを足すと交差項が抜けます。二乗でも `(a0+a1)²=a0²+2a0a1+a1²` の中央が残ります（奇数の素数を使う理由です）。

比較は「x>y なら1、それ以外は0」を例に考えます。2人・p=7で、yのシェアを両方0に固定します。xのシェア a0,a1 を変えると次の4通りです。

| 人0の a0 ＼ 人1の a1 | 0 | 6 |
|---|---:|---:|
| 0 | x=0 → 比較0 | x=6 → 比較1 |
| 1 | x=1 → 比較1 | x=0 → 比較0 |

どんな手元の計算法でも、人0の出力は自分の a0 だけから作る数 F(a0)、人1は G(a1) と書けます。F,Gは特定の式ではなく、「各人が選んだ計算法」の名前です。新しいシェアの合計 F(a0)+G(a1) が比較の0/1を復元する必要があります。

```text
左上＋右下の出力 = F(0)+G(0)+F(1)+G(6)
右上＋左下の出力 = F(0)+G(6)+F(1)+G(0)
```

右辺は同じ4つの数を並べ替えただけなので、余りも同じはず。ところが表では前者0+0=0、後者1+1=2で、7で割っても違います。つまり**手元の計算法をどう選んでも、この4通り全部には答えられません**。このモデルの比較には通信が必要です。一般の奇数の素数pでも6をp−1にすれば同じ表になり、0と2の余りは異なります。3人以上は他の人のシェアを0に固定すると、他の出力は両辺に同じ回数現れて消えます。これは上で定めた加法的シェアのモデルについての理由で、別の暗号方式まで否定しません。

## どこへ提出するか

| 小問 | 作るもの |
|---|---|
| `add-shares` | linear.py の add_shares |
| `add-constant` | 同 add_constant |
| `mul-constant` | 同 mul_constant |
| `no-communication` | 証拠に出た4操作だけをキーにしたJSON |
| `transfer` | 上の3関数と、8操作すべての communication_rounds |

コードの4欄は、現在の linear.py を「提出」で送ります。`no-communication` は、証拠にある**自分の4つの名前**を読み、各操作の式を自分の行だけで作れるか判断します。回答欄には1行のJSONを書きます。書式は `{"画面の操作名": 判定した整数, …}`。引用符の中を表示された名前に、整数を自分の判定に置き換え、4組をカンマで区切って `{}` で囲みます。これは書式の説明なので、そのまま提出せず自分の4組を完成させます。

キーは表示された4つちょうど。値は0以上の整数で、通信側は1でも2でも受理します。「公開テストを実行」で結果を確認してから「提出」へ進みます。誤答は1回10点、ヒント15個の合計は94点です。

## 次に確かめること

`transfer` は、別の p・人数でも `c(x+y)+c` を計算できるか確認します。これは結果の和と形式の検査で、すべての秘密計算の安全性を証明するものではありません。元のシェアを適切な乱数で作ること、誰に何を見せるかという条件も必要です。
