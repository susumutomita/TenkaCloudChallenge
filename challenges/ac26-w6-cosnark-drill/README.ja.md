# 二人で分担して、秘密の数を掛ける

> Advanced Cryptography Program 2026 の独立した非公式の補助教材です。
> 講座や運営者による承認・提携はありません。問い合わせ先は TenkaCloud です。

Week 6 / order 605 / difficulty 3 / 200点 / 40〜60分 / draft。

二人が元の数を集めずに、足し算・掛け算を分担する練習です。
「証拠を確認」で自分の数を読み、問題文の14行を順に試し、8個の回答欄を埋めます。
これは共同で証明を作る co-SNARK の算術部分を取り出した模型で、完全な証明生成ではありません。

## 参加者の操作

1. Portalで起動し、「証拠を確認」の代入文を `python3` に貼ります。
2. 問題文の行を上から実行します。回答欄がある行では、自分が出した数を提出します。
3. Pythonを開けなければエディタを使います。対応する行のコード全体で `return None` を置き換え、最後の式に `return` を付けます。前段の名前は用意済みです。上から埋めて「公開テストを実行」すると自分の値が出ます。

あなたは二人分を見渡す見学者です。人0が持つのは `w0[0],w1[0]`、人1は
`w0[1],w1[1]`。説明用に戻すw・A・Bや事前のa・b全体は、当事者へ渡す情報と区別します。
実際に送り合うのは `A_sh[i]−a_sh[i]` と `B_sh[i]−b_sh[i]` の余りです。

| 回答欄 | 確かめること | 点 |
| --- | --- | ---: |
| shares | 二人へ配るかけら | 20 |
| ashares | Aを各人の手元で作る | 25 |
| aopen | 分担と直接計算の一致 | 20 |
| bshares | 別の掛ける数でBを作る | 25 |
| crossmul | かけら同士の積で抜ける二項 | 30 |
| beaveropen | 差のかけらからd,eを共有 | 25 |
| cshares | d,eを使って積のかけらを作る | 30 |
| csum | かけらを足して積Cを受け取る | 25 |

各欄のヒントは「仕組み → 一桁の見本 → 自分の数での手順」の3段、各2点です。
全ヒント48点、誤答1回10点。必要な式は無料の問題文にもあります。

## 数の作り方と保証範囲

数はverifierだけが受け取る `FLAG_SEED` から再現可能に作ります。割る素数は
講座の例で使う97・101・89を除外します。小さい数が個別に教材と重なることや、
答えが入力の数と偶然一致することはあります。

隠す数は0からp−1まで全部を候補とし、0・等しい値・秘密と同じ値を除外しません。
積の比較が必ず不一致になるような引き直しもしません。それをすると、秘密に応じて
隠す数の分布が変わるからです。かけら同士の積は一般には使えませんが、抜けた二項の
余りが0の回は偶然一致します。一桁の見本では不一致を直接確かめられます。

ローカルは自習用です。学習者には全体を見せており、本物の秘密は守りません。
participant imageにはstarter・公開テスト・Portal APIだけを入れます。
生成器・期待値は別のverifier、参照解・mutationはauthor imageだけです。
Workbenchにfixtureのseedを渡しません。公開された一方向の配布識別値で提出を
今回の配布に結び付けますが、これは認証ではなく、正誤はverifierだけが決めます。

Workbenchの18163番だけを127.0.0.1へ公開し、verifierは内部ネットワーク限定です。
両サービスは非root・読み取り専用・権限とメモリ/PID数の制限付きです。
Dockerを管理する本人からの秘匿や競技の信頼境界は保証しません。

## ローカル確認と終了

```bash
make inspect
make test              # 未記入のstarterでは失敗するのが正常
make test-one ID=shares
make verifier-down     # 終了時: 残っているverifierとネットワークを止める
```

`make inspect` と `make test` はverifierを起動したまま残すため、終了時には
`make verifier-down` を実行します。クラウド資源は作りません。ローカルDockerの
CPU・メモリを使い、終了するまでverifierは動き続けます。
