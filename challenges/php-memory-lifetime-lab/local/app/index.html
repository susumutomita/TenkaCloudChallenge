寿命の切れたメモ / Stale request note

小さな C プログラムを隔離コンテナで動かし、解放あとの参照・スタックとヒープ・直し方を観測します。実 PHP の攻撃や CVE の再現ではありません。補足ノート

進め方
  1. 下のボタンで「壊れた版」を ASan 付きで動かし、診断と OBS 行を読む。
  2. （任意）gdb の一括表示で、ポインタ変数と指し先の違いを見る。
  3. クイズに答える。
  4. 教材用の無害関数 record_lab_event をハーネス経由で呼ぶ。
  5. 修正版で「拒否＋正常系」を確認する。
  6. 各ステップで出た TC{...} を Portal の対応チェックポイントへ提出する。

答えの形はどれも TC{ に続く英数字です。ヒント無しでも画面の結果だけで提出できます。

1. 予測してから観測（ASan）

ワーカーが、前のリクエストのヒープメモへの印を残したまま解放し、次の処理で読んでしまう版です。動かす前に予想してください。

2. gdb で場所を見る（任意）

非対話の gdb で、停止位置のフレーム・ローカル・ポインタ変数を表示します。失敗しても本編は進められます。

3. スタックとヒープ

次の説明のうち、正しいものを選んでください。

4. 無害な教材イベント

あらかじめ用意した record_lab_event("checkpoint") を、ハーネスが意図的に実行します。脆弱性を使った制御奪取ではありません。ハーネスが fd 3 で受け取った記録だけが証拠です。

5. 修正版の回帰

修正版は、リクエスト終了時に保持ポインタを消します。同じ手順のあとに拒否し、正常な確保→利用→後片付けは残ることを確認します。
