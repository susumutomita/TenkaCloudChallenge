# 名前を出さずに、二票目を見分ける

> Advanced Cryptography Program 2026 に対応する非公式・独立教材です。
> 提携・公認ではありません。お問い合わせは TenkaCloud へ。

Week 6 / 順序655 / 難易度3 / 200点 / draft / 目安30〜45分。

一人一票の投票で、使用済みの印（nullifier）を追います。六件の依頼を処理し、
確認してから印を記録する理由を確かめます。最後は小さな模型で、別人の印が
重なる例を自分で構成します。

## 参加者の進め方

1. Portalで開始し、「証拠を確認」の `p =` から `attempts =` までの代入文を
   `python3` に貼ります。1行目の印を計算し、`label` 欄へ提出します。
2. 最初の七行を順に進めます。Portalのエディタでは `return None` を各行の
   コード全体へ置き換え、最後の式に `return` を付けます。
   「公開テストを実行」で自分の計算結果を確認します。
3. 最後は、同じ印になる別の秘密の数を自分で選びます。数を直接提出するか、
   `collision` を自分で実装します。七つの掲載コードを写しただけでは未完了です。

用語、必要な規則、一桁の見本は無料の日英の問題文にあります。任意ヒントは
各欄「仕組み → 見本 → 自分の画面での手順」の3段、各2点、計48点です。
誤答は10点減点です。

| 回答欄 | 確かめること | 点数 |
| --- | --- | ---: |
| label | 使用済みの印の計算 | 25 |
| repeat | 投票内容を変えても同じ印 | 25 |
| scopes | 別の投票番号を分ける | 25 |
| accept | 確認済み・番号・未使用を調べてから記録 | 25 |
| count | 届いた数ではなく受理した記録の数 | 25 |
| message | 内容を混ぜた誤った印の動作 | 25 |
| unchecked | 確認を省いたときの不正な受理 | 25 |
| collision | 別の秘密の数で同じ印になる例を構成 | 25 |

## 模型と境界

見本はp=7、secret=2、scope=1です。「秘密の数の二乗＋投票番号」をpで割った
余りなので印は5。pは5か7、secretは1〜p−1です。秘密を含む入力を見学用に
表示します。この模型は簡単に印が重なり、匿名性はありません。暗号用のハッシュ、
参加資格の証明、ZKの検証、同時実行する投票サービスは実装しません。

`verified` は確認済みの練習用依頼を表します。本物の証明では参加資格・印・
投票番号・投票内容の結び付きを検証する必要があり、自己申告の真偽値では
代用できません。ここでは届いた順に記録を更新する計算を扱います。
別番号でも模型の印が重なる場合があり、この小さな式で本物の追跡困難性は示せません。

`FLAG_SEED` は採点用コンテナだけに渡します。参加者イメージは公開テスト、
スターター、Portal APIだけを含み、問題生成器・模範解答・非公開テストは含みません。
公開の識別値で提出を開始回に結び付けますが、これは認証ではありません。
正誤は別の採点用コンテナだけが判定します。実行コードへは取得済みの公開データだけを
渡し、採点用URLや提出の識別値は渡しません。Linuxのseccompで通信や他プロセスの
記述子を使う経路を禁止し、子プロセスにも引き継ぎます。親のメモリ参照を禁止し、
CLIにも同じ制限を適用します。親への停止要求やリソース制限の変更も禁止します。
実行終了時に残った子プロセスを終了し、制限を設定できなければコードを実行しません。

Workbenchの18167番を127.0.0.1へ公開し、採点用ポートは内部限定です。
両コンテナは非root、読み取り専用でリソースを制限します。Dockerを操作できる
人は自分のイメージを調べられます。本物の投票や秘密を守る環境ではありません。

## ローカル確認と終了

この問題のディレクトリで実行します。

```bash
make inspect
make test              # 未記入のスターターでは失敗するのが正常
make test-one ID=label
make verifier-down
```

CLIは編集したスターターをDockerへ標準入力で送り、ホストのPythonや共有パスを
必要としません。inspect/testは採点用コンテナを残すため、最後に `make verifier-down`
で終了します。クラウドのリソースは作りません。停止までローカルのCPU・メモリを使います。

作者は `make reference-test` で誤実装、実際の公開テスト経路、記録の更新と提出の境界を
確認します。リポジトリ直下の `make install` と `make agent-gate` も実行します。
実AWSイベントと人によるイベントリハーサルは任意で、未実施です。
