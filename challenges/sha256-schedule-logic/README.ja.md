# SHA-256 その 2: ビット演算とメッセージスケジュール

回転とシフトの違い、σ0 σ1 Σ0 Σ1 の 4 種類のずらし量、Ch が選択回路であること、Maj がパリティではないこと、そして 16 ワードを 64 ワードへ広げる漸化式。SHA-256 の配線を全部自分で書く。

SHA-256 を自分で追える手続きに変える 3 問シリーズの 2 問目。1 問目で作った 512 bit ブロックが入力になる。圧縮ループの手前、ビット演算のすべてをここで実装する。

Workbench のエディタ (`schedule.py`) に 8 つの関数があり、うち 5 つが意図的に壊れている。壊し方はどれも 1 行で、どれも実際によくある間違いにしてある。回転をマスクし忘れて 32 bit を超える、σ1 の第 3 項をシフトではなく回転にする、Σ0 に Σ1 のずらし量を書く、Ch の否定を落とす、Maj をパリティで書く、message schedule の 4 項を加算ではなく XOR で繋ぐ。

採点は 6 checkpoint 独立。rotate (20) は回転とシフトを 1 語ずつ手で出す予測、mux (25) は Ch を選択回路として理解しているかの確認、dependency (30) は 1 bit 反転が 64 ワードのどこに最初に到達するかを漸化式から導く問題、sigma (45) は rotr と 4 つの σ、logic (30) は Ch と Maj、schedule (50) は expand_schedule を隠しテストで検証する。

3 つのコード checkpoint は意図的に独立にしてある。schedule は「W[i] がどの 4 語を読み、それを加算するか」だけを見る。期待値は学習者自身の σ を使って計算するので、σ が間違っていても漸化式が正しければ schedule は通る。σ の正しさは sigma checkpoint の担当で、1 つの間違いを 2 回減点しない。

公開テストは意図的に不十分にしてある。σ を仕様のずらし量と突き合わせず、Ch と Maj を混合セレクタで区別せず、展開するブロックは全ゼロだけ。全ゼロでは XOR と加算が一致するので、4 項を XOR する実装でも全部通る。隠しテストは σ の GF(2) 上の線形性、Maj の対称性、そして展開全体が XOR に対して線形でないこと (= 桁上がりが本当にあること) を検査する。

mutation suite (local/mutation.py) が 33 変異を kill することを CI で担保する。加えて checkpoint の独立性そのものも検査する。σ を壊した変異が schedule suite に漏れていないことを assert してある。等価変異 5 種は意図的に除外し、理由を mutation.py の冒頭に書いた。うち 2 種は実際に survived してから外したものだ。

## 解説

## 何を確認したか

### 回転とシフトは別物で、両方が必要

回転は 32 ビットの置換です。ビットは 1 つも失われず、立っているビットの数は変わりません。シフトは失います。

SHA-256 は両方を使い、どちらを使うかで意味が変わります。σ0 と σ1 は回転 2 つとシフト 1 つ、Σ0 と Σ1 は回転 3 つです。σ にシフトが入っているのは偶然ではありません。シフトがビットを落とすからこそ message schedule は単射でなくなり、64 ワードから 16 ワードを逆算できなくなります。Σ は圧縮関数の中で状態を撹拌するだけなので、情報を落とす必要がありません。

ずらし量は 4 種類あって覚え違いを誘います。σ0 は (7, 18, 3)、σ1 は (17, 19, 10)、Σ0 は (2, 13, 22)、Σ1 は (6, 11, 25) です。記憶ではなく仕様表を見るべき場所です。

Python で書くときの罠がもう 1 つあります。`value << (32 - amount)` の結果は 32 bit を超えるので、`& 0xFFFFFFFF` でワードに戻す必要があります。忘れると値は静かに巨大化し、σ もスケジュールも全部おかしくなりますが、例外は出ません。

### Ch は選択回路、Maj は多数決

Ch(e, f, g) = (e AND f) XOR (NOT e AND g) を式として覚えると何も分かりません。1 bit 分だけ書き出すと正体が見えます。e のビットが 1 なら f のビットが出て、0 なら g のビットが出る。つまり 32 個並んだマルチプレクサで、e がセレクタ、f と g が選択肢です。

Maj(a, b, c) = (a AND b) XOR (a AND c) XOR (b AND c) はビット位置ごとの多数決です。入力が 3 つなので必ず 2 対 1 が付きます。XOR で書けるのは、3 つのペア項のうち浮いている 1 つが高々 1 つしかないからで、OR で書いても同じ値になります。

よくある誤解は Maj をパリティ `a ^ b ^ c` と混同することです。1 bit で見ると、一致するのは全 0 と全 1 の 2 通りだけで、残る 6 通りで食い違います。それでも fixture が 1 つだと通ってしまう種類の間違いなので、隠しテストは 1 bit の真理値表 8 行を全部回します。

### message schedule は加算で、XOR ではない

W[i] = W[i-16] + σ0(W[i-15]) + W[i-7] + σ1(W[i-2]) を mod 2^32 で足します。XOR は安く見える代用品で、間違っている理由がはっきりしています。XOR に桁上がりが無いので、あるビット位置の情報がより上の位置へ伝わりません。message schedule が存在する理由そのものである拡散が起きなくなります。

これは検査もできます。回転・シフト・XOR はすべて GF(2) 上で線形なので、4 項を XOR する展開は全体として線形になり、`expand(a XOR b)` がちょうど `expand(a) XOR expand(b)` になります。加算には桁上がりがあるのでそうなりません。隠しテストはこの性質を直接見ています。固定の期待値ではなく関係なので、暗記では通りません。

### 1 bit はどこまで伝わるか

dependency checkpoint の答えは 1 つの式ではありません。W[i] が読むのは i-16、i-15、i-7、i-2 の 4 つですが、W[0] から W[15] は入力なので、計算されるワードは添字 16 以上だけです。したがって入力の添字 k を最初に読む計算済みワードは、k+16、k+15、k+7、k+2 のうち 16 以上になる最小のものです。k=0 なら 16、k=1..8 なら k+15、k=9..13 なら k+7、k=14,15 なら k+2 になります。

途中で差分が打ち消えることはありません。σ は 1 bit の差分を 2 つか 3 つの別々の位置へ送り、その XOR がゼロになることはないからです。

## 公開テストが通っても終わりではない

この問題の公開テストは、σ を仕様のずらし量と突き合わせず、Ch と Maj を混合セレクタで区別せず、展開するブロックは全ゼロだけです。全ゼロでは XOR と加算が一致するので、4 項を XOR する実装でも全部通ります。

隠しテストは境界値 (0、0xffffffff、0x80000000、0x55555555) と seed 由来の語を回し、σ の線形性、Maj の対称性、Ch の「両選択肢が同じなら結果もそれ」という性質、そして展開が XOR に対して線形でないことを検査します。
