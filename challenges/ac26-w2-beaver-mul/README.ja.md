## 算術とその限界

shareは数の断片で、すべて足して素数pで割った余りが元の数です。a、b、`c=a*b % p` の
shareを用意します。2つの差 `d=x-a` と `e=y-b` をpで割った余りとして公開し、展開します。

```text
x*y = (a+d)*(b+e) = c + d*b + e*a + d*e   （pで割った余りとして）
out_i = (c_i + d*b_i + e*a_i) % p
```

公開定数d*eは**全体の合計**へ1回分だけ加えます。party0だけに加える方法が一例ですが、
合計が同じ別の分け方も受け入れます。本文のp=7、d=3/e=4の例では、定数を加える前が
`[0,5,5]`、加えた後が `[5,5,5]`。合計の余り1は `5*3` と一致します。全員に加えると
`[5,3,3]`、余り4になります。listの代わりのtuple、bool、範囲外の整数は宣言した
返り値の型・範囲を満たしません。

`open` の範囲は表現の契約です。余りを取る前の合計でも、後続の剰余演算で積が一致する
場合があります。範囲外というだけで剰余として誤りとは限りません。2つの開示は互いを
待たないため、メッセージを1ラウンドへまとめられます。`rounds()` はこの最小回数を
問い、任意に遅い実行方法の回数を問うものではありません。

このプログラムは全参加者をまとめた算術模型です。Inspectの全shareリストを足せば元の値を
復元できます。実MPCでは各partyが自分のshareを持ちます。差を公開しても秘匿性を保つには、
マスクが入力と独立で一様、観測者が復元できず、一度きり使用するという条件が必要です。
固定したdに対し、各入力候補xには `a=(x-d)%p` が1つ対応し、この条件下で確率が等しく
なります。単に未知というだけでは足りません。正しい積は、安全な前処理・認証された通信・
不正な参加者への対策まで証明しません。教材の非退化なテスト値は算術の誤りを発見するための
もので、実際のマスク分布全体を再現するものではありません。

同じaを使い回した `d1-d2` で何が消えるかを説明してください。次の
`ac26-w2-private-aggregate` へ進む前に、独立した乗算の個数、消費する三つ組の個数、

## 実行境界と作問者の検証

Workbenchイメージには公開教材を入れ、非公開ポートのverifierイメージにfixtureと隠し
検査を置きます。両サーバーは非rootで動き、TiniをPID1にします。信頼するWorkbench親は
既存のデプロイseedと `tcw1` 準備契約を維持します。提出コードの子プロセスには空から
作る環境とソース・関数引数だけを渡し、無関係なファイル記述子を閉じます。コード実行前に
Linux seccompでファイルopen、ネットワーク、別プログラム実行、プロセスへのシグナル、
残存するSystem V IPCを禁止します。資源上限・実時間の期限・プロセス群の終了で実行を
制限し、Tiniが子孫を回収します。

公開・非公開の検査は信頼する親で返り値を判定します。提出コードのstdoutや終了コードを
採点結果にはしません。毎回の新しいcall IDは古い応答・先行印字を拒否しますが、
**Python関数の実行を証明するものではありません**。算術の最終判定は親が行います。
隠し入力や提出側の任意ログは返さず、公開の初期化エラーは提出ファイル名・行・例外型だけを
表示します。

これは検証したプロセス制限であり、Dockerやホストを管理する人への秘密保持保証では
ありません。自習用の算術演習で、実MPCの安全性の認定ではありません。クラウドアカウントや
AWS資源は使いません。

`make reference-test` はauthorイメージで8件のmutationとLinux実行境界の検査を行います。
リポジトリの `make install && make agent-gate` がcatalogを別途検証します。実Portal
コンポーネント/APIの再実行手順と、元読者がwriteupを見たという制約は
`local/tests/hidden/READER.md` に記録しています。

## ファイル属性操作の隔離追加
