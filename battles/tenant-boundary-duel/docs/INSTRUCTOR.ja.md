# 指導者用：到達目標・採点・評価

このファイルは開催者用。参加者の画面や配布bundleへ入れない。

## 進行と学習成果

25分の演習と10分の振り返りを想定。前半で認証と認可を分け、操作・対象・ログの関係を説明する。後半の委任で「別組織は全部拒否」も不十分だと観察し、許可の複数経路を安全に組み立てる。公開テストを一度失敗させて修正した経緯も聞く。勝敗は学習成果の代替ではない。

作者による参加者の読解確認：最初に選ぶノートと操作、観測するallowed・組織名・読取回数、次に渡す証拠、式の入力・演算子・成功条件が参加者画面から分かる。自己申告・委任・停止済み本人・認可は使用時までに定義される。3段階の無料手がかりは仕組み→小さな例→実際の式と操作の名前を使った手順。この確認を独立した人間の試遊とは呼ばない。

## 参照実装と反例

```text
actor.active && ((actor.tenant == document.tenant &&
  (action == "read" || actor.role == "editor")) ||
  (action == "read" && grant.valid))

event.allowed && event.actorTenant != event.documentTenant &&
  !(event.action == "read" && event.grantValid)
```

全拒否は正規業務を失う。自己申告とノート所属だけの比較は偽の申告で通る。`blue`の固定文字列は未知の組織名で破れる。所属だけの比較は読者の変更を許してしまう。本人の停止状態を一方の許可経路にしか掛けないと、停止済みの人が委任経路を使える。読む委任を変更にも適用するのは操作範囲の拡張。検知を常にtrueにすると正規操作・拒否を警報にし、常にfalseは過去の成功した越境を見落とす。

## 採点根拠

認可は停止状態2×所属関係2×役割2×操作2×委任2×自己申告2＝64組。サーバーが操作に合わない読む委任を無効にしてから評価する。正規業務は16組、拒否すべき組は48組。未知の組織名はmatchSecretから導き、参加者へ期待値やfixtureを配らない。検知は各組の過去の許可/拒否ログ2種類、計128組。現時点の認可式で攻撃を全部拒否していても、過去の成功ログを検知できる必要がある。

防衛点は40点の拒否率、40点の正規業務率、20点の検知率の合計から再試験被害を引く。全拒否の高得点化を防ぐため正規業務を独立評価する。部分点は診断用で、満点以外を安全な実装と認定しない。再試験被害は不正なノートと操作の組ごとに25、最大4試行で100。繰返しによる読取回数は増えても同じ組を二重採点しない。防衛側の確認後に攻撃が来ても、最終被害で精算する。

防衛点には対策前の試行、式の適用、攻撃役の再試験と完了、明示的な再検証が必要。単なる時間経過・デプロイ・準備完了で点を作らない。各ラウンドの式・検証率・被害・役割・点数を履歴に残す。同じ操作IDと同じ内容の再送は状態と点を変えず、内容を変えた再送は拒否する。本体HTTPのrunId契約と公式得点履歴は連動テストで確認する。

## 事前・事後評価

採点は各0〜2点、計8点。0＝説明できない、1＝表面的な正答、2＝根拠となる証拠と反例を説明できる。個人情報は集めず、任意のチーム名と評価値だけを主催者の手元に記録する。事前はプレイ前、事後はリプレイを見せ、同じ能力を別の名前・場面で問う。

| 能力 | 事前 | 事後 | 2点の基準 |
| --- | --- | --- | --- |
| 境界の発見 | ログイン済みなら他社のノートを読めるか | 保存成功ログから原因を説明 | 本人情報と対象の所属を照合していない証拠を指す |
| 対策の実装 | 全拒否と自己申告比較の問題は | 未知の組織・停止者の反例を書く | 正規業務を残し、両経路に停止条件を掛ける |
| 検知 | 拒否ログだけで被害を測れるか | 合法な委任と成功した越境を分ける | allowedと関係と操作範囲を同時に見る |
| 転用と限界 | 非同期処理へ同じ条件をいつ適用するか | 委任を失効した後のエクスポートを説明 | 実行時と結果取得時の再認可、競合や保存層の未検証を挙げる |

目標は平均点の改善と、全拒否・自己申告依存・停止条件の漏れを反例で説明できる割合。学習効果の数値は実測前に宣伝しない。初回パイロットは2席または複数の独立2席試合で行い、離脱点・公開テストの改善回数・事後評価を記録する。複数試合の同時運用・運営ダッシュボード・受講者分析はこのPRで製品化していない。

## 既知の限界

限定式の実装体験であり、任意の実サービスの安全なコードを書ける認定ではない。委任発行・署名・期限・失効、非同期export、一覧、キャッシュ、DBの行単位認可は実装範囲外。別経路でも同じ本人/対象/操作の関係を保つ必要を振り返りで扱う。実攻撃や実環境の安全性・公式講義の採用を主張しない。
