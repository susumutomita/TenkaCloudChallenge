# テナント境界防衛戦

架空の共有ノートを守る、2チーム・4ラウンドの独自Battle。本人確認済みの読者で別組織のデータを読む・変更する → 操作ログとノートの変化を観察する → 認可式と検知式を自分で実装する → 公開テストで失敗を改善する → 相手の再試験と未知のデータで確認する。

既存の `session-defense` は予算内の対策選択を学ぶ。この問題はサーバー固定の本人・対象・役割を照合する実装へ進み、認証の強化だけではデータ境界を守れないことを扱う。新しい名前を付けたセッション教材ではない。公式認定・講義の複製・過去問ではない。

## 起動と参加者の道筋

Bun 1.3.11で、このディレクトリから実行する。

```sh
make install
make dev
```

表示される alpha / bravo のURLを2つの新しいブラウザ環境で開く。両者が「準備完了」。攻撃役は Orange notebook を選んで「読む」。`allowed`、本人の組織とノートの組織、読取回数を比べる。「証拠を渡す」で防衛役へ。防衛役は画面のルール・文法・無料の3段階の手がかりを読み、2つの式を編集する。公開テストのFAILを改善して適用し、相手が再試験する間に「正規業務・境界・検知を再検証」。役割を交代する。後半には読む操作だけを許す委任が追加される。

式は関数の本体に相当する限定した条件式。`== != && || ! ()`、文字列、真偽値と定義済みの入力だけを使う。ループ・関数呼出し・代入・JavaScript実行はない。最大1024文字、128語、深さ16。必要なルールと文法は無料で画面にある。未知の組織名、役割、停止済みの人、委任、偽の自己申告に同じ式を適用する。

公開テストは各ラウンド8回まで。各段階180秒、試行券は対策前と再試験にそれぞれ4枚。対策前の操作・起動・待機・公開テストは0点。攻撃点は再試験で通った不正なノート/操作の組に25点、同じ組は1回、最大100。防衛点は `floor(40×境界成功率 + 40×正規業務成功率 + 20×検知成功率) − 被害`、最低0。防衛点には対策前の試行、式の適用、相手の再試験完了、明示的な再検証がすべて必要。合計点の高いチームが勝ち、同点は引き分け。時間切れだけで防衛点を得られない。

`?lang=en#seat=…`で英語。dev harnessは127.0.0.1:5678限定、別ポートは `PORT=5679 make dev`。Ctrl-Cで停止。harnessはメモリ保存で再起動すると試合と席キーが消える。本体hostは主催者選択・2席の認証・SQLite・公式得点履歴を使う。両者の検証を混同しない。

## 安全境界と限界

合成ノートと演習内の操作のみ。実Google/Microsoft・企業環境、実資格情報、個人情報、マルウェア、外部サイトや任意URLは扱わない。dev席キーとゲームの入力を分離し、本人の組織・役割・有効な委任はサーバーが固定する。サーバー生成のmatchSecretから問題識別子と未知の組織名を導く。任意コードをホスト権限で実行しない。

閲覧委任はこのラウンド・本人・ノート・読む操作に限定し、入力 `grant.valid` で模型化する。実OAuth/OIDCや暗号署名・委任発行UIは未実装。キャッシュ、一覧API、非同期エクスポート、失効と処理中の競合、保存クエリの認可はこの1問で実装していない。指導者はこれらへ学びを転用する説明を求める。クリアは実組織の安全を保証しない。第三者の人間による試遊は任意の開催前リハーサル。

AWS・Docker・課金資源・Region指定はない。費用はローカル実行機の時間と保存領域。本体hostを停止し、主催者が保存した試合を削除すれば片付けは完了。クラウドteardownやデプロイは不要。
