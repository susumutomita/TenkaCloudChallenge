# 暗号教材で再現する仕組みと範囲

[English](MODELS.md) · [遊び方へ戻る](../README.ja.md)

遊ぶ前に覚える必要はありません。必要な計算と例はお題に表示されます。この文書は、各お題で何を確かめているかを振り返るためのものです。小さい数は手計算をしやすくしますが、秘密も簡単に探せるため、実データの保護には使えません。

## 暗号化・復号・署名

| お題 | 手を動かす部分 | 教材の範囲 |
| --- | --- | --- |
| シーザー | 3つの記号にずらす数を足し、一周したら先頭へ戻す | 元の数と暗号文の1組から、ずらした数が分かる |
| Vigenère | 繰り返す3個の鍵のうち、指定位置の鍵を足す | HUNTには3件の記録ではなく、全鍵位置の材料が必要 |
| Rotor | 4記号用の2つの車輪の配線をたどる | HUNTは初期位置を求める。1組の公開から候補が1つになるとは限らない |
| エニグマ模型 | 車輪を進め、配線→反射板→逆の配線をたどる | 0〜3の1文字。実機の26文字・複数ローターは再現しない |
| RSA暗号化 | 公開された割る数で余りを取りながら、元の数を繰り返し掛ける | 安全な符号化を省いた小さな教科書RSA。HUNTは公開値を因数分解する |
| RSA復号 | 配られたお題専用の秘密鍵で、暗号文から元の数を戻す | 暗号化のお題とは独立。配布鍵はHUNT対象外 |
| 楕円曲線の足し算 | 与えられた式で2点の足し算・同じ点の足し算をする | 署名にも使う演算の部分であり、署名全体ではない |
| ECDSA | 配布鍵・今回だけの数・逆元表で署名の2つの数を計算する | 小さな曲線とお題専用鍵。HUNT対象外で、実用の署名強度はない |

暗号化と復号は、それぞれ独立して採点します。エニグマの反射板から戻る道は、1回の暗号化の内部手順です。

## 秘密を分ける・隠したまま計算する

**秘密分散**：シェアは「番号と数」の組です。標準のShamir方式では5個を作り、異なる番号が3個あると元の秘密を戻せます。別チームや別世代のものは混ぜません。HUNTで答えるのは、すでに見えるシェアではなく、復元した元の秘密です。

**秘密計算（MPC）**：自分の入力に、受け取った隠す数を足し、送った隠す数を引きます。全員の小計を合計すると、対になった隠す数が打ち消し合います。この打ち消しの模型であり、任意の共同計算を実行する仕組みではありません。

**準同型の足し算**：個々の中身を復号せず、暗号文の成分どうしを足します。審判が対応する隠す数を取り除くと、中身の合計に対応することを確かめられます。操作名にはFHEが残っていますが、このお題は足し算だけの模型です。完全準同型暗号（FHE）は足し算と掛け算を組み合わせた計算も扱います。

## ゼロ知識証明と証明システムの部品

**SchnorrのPROVE** は、公開値yに対応する秘密xを題材にします。端末内にxと今回だけの隠す数rを保ち、最初の数aを送信→検証者の問いeを受信→応答zを計算、の順に進みます。検証者はxやrを受け取らず、公開値で計算を検査します。1つの証明の会話であり、暗号化・復号の組ではありません。対象は専用のxで、Shamirのシェアや数独の解ではありません。

この模型では秘密の候補が最大11通りしかありません。合格しても、回答前から秘密を持っていたとは保証できず、同じ小さな数で何度繰り返しても実用の安全性にはなりません。模擬会話で説明する「公開値y以上の情報を漏らさない性質」と「不正な主張を通しにくい性質」は別です。実装は[schnorr.ts](../game/src/schnorr.ts)、安全性の前提は[RFC 8235](https://www.rfc-editor.org/rfc/rfc8235.html#section-6)を参照してください。

**旧数独のPROVE** は、数字を付け替えて盤面の一部を公開する模型です。元の解を知る審判を信頼します。保存済み試合には、この穴埋めと表の使い回しへの攻撃が残ります。完全なゼロ知識の数独プロトコルではなく、新規試合のPROVEにも使いません。

**SNARKの準備** は、各行の計算と、配線でつないだ値の一致を7で割った余りで検査します。行が正しくても、つなぐ値が違えば全体は不正です。計算を検査条件に変える考え方を扱い、短い暗号学的な証明そのものは作りません。実装：[snark.ts](../game/src/snark.ts)。

**STARKの準備** は、同じ数を2回掛ける計算のつながり、多項式の余り、1回の折り畳みを検査します。多項式は、定数・Xの何倍か・X²の何倍か、などを足した式です。必要な式はお題で与え、導出は求めません。Merkle木による固定、検証者のランダムな問い合わせ、繰り返すFRI検査、秘密を隠す処理は省いています。折り畳みだけが正しくても、実行全体が正しいとは言えません。実装：[stark.ts](../game/src/stark.ts)。

## ほかの実験

**識別不可能性難読化（iO）**：有限個の入力についてプログラムの答えと、答えが出る確率を比べます。「同じ働きをする」と「出力の分布も同じ」は別の検査です。小さな例で定義の一部を確かめるもので、一般のプログラムを安全に難読化する実装ではありません。

**アナモルフィック暗号**：通常の暗号文の候補から、追加の秘密表で目的のビットになるものを選びます。候補選択・通常復号・受理くじの確率を別々に出題します。疑似ランダム関数の代わりに6項目の表を使い、教材の試行列も論文の独立な選び直しとは異なります。1通の平均分布が一致しても、繰り返し送信の安全性は保証しません。実装：[anamorphic.ts](../game/src/anamorphic.ts)、背景：[Persiano・Phan・Yung、EUROCRYPT 2022、5.1節](https://iacr.org/archive/eurocrypt2022/132760134/132760134.pdf)。

**封じてから開くじゃんけん**：隠す数を使って先に手を固定し、後から審判に中身を渡します。両者の内容が受理されるまで公開を遅らせます。隠す数の使い回しは予測の手がかりになります。小さな数と信頼する審判による教材で、実用の公平な交換プロトコルではありません。

## 遊びながら確かめる

無料の図解と一桁の練習で仕組みを見て、お題のヒントでは「仕組み→小さい例→自分の数字を使う各計算」と進みます。最終解答は自動入力しません。

公開するものとHUNTの回答対象は[LEAK→公開記録→HUNT](LEAK-HUNT-RULES.md)、実行環境の信頼境界と旧試合は[運営ガイド](../OPERATOR.md)を参照してください。
