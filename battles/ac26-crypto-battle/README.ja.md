# 暗号バトル

ヒントは選んだ1題を読んで計算・提出してから、次のお題へ進みます。シーザーの3段と、かけらのお題の最終手順をこの流れに整理しました。通常の5分期限とヒント料金は同じです。検証範囲と未確認事項は[読解確認記録](dev/HINT-READING.md)に記載します。

盤面の上には「遊び方」「暗号を図と式で見る」「一桁の穴埋めで練習」「ルール一覧」の入口を表示します。どれも任意です。別のスクロール領域で開き、閉じると元のお題・入力・スクロール位置へ戻ります。開いている間も開始済みの試合の時間は進みます。練習は余り → 秘密分散 → 復元 → 公開の危険 → MPC・ZK・FHE・シーザー・じゃんけんを小さい数字で追います。入力せずに読み進めることもできます。
解説は「今やること・式・1個の空欄」を先に表示し、計算の手順と理由は折り畳みから読めます。答えを確認した後も、要点は1文です。

盤面は「いまのお題 → 答え方と得点・公開リスク → 回答」にまとめます。MPC は足す覆面の合計・引く覆面の合計・自分の数への足し引き・余りへの変換を、実際の数字で表示します。結果は回答エリアの上へ表示します。ヒント、公開状況、公開記録、保管庫は必要なときに開きます。

お題一覧は回答中も表示し、未処理件数・種類・締切・選択中を確認できます。カードは締切順で、クリックまたは Tab と Enter / Space で直接選べます。新しいお題は短い到着通知とカードの「到着」で知らせ、選択や入力途中の回答は変えません。「締切間近」「期限切れ」「完了」は文字でも区別します。直近の結果を一覧の下へ残し、この画面で確認した回答の獲得点を表示します。狭い画面や件数が多い場合は一覧内をスクロールできます。

「暗号を図と式で見る」から、割った余り・秘密分散・MPC・ZK・FHE・シーザー暗号を各 4〜5 ステップで読めます。何をしたいか、仕組み、一桁の計算例、今の入力欄の順に進みます。MPC・FHE・シーザー暗号は入力欄の直前からも開け、最後にその Order の数字を使った未計算の式を表示します。解説は得点や試合状態を変えず、いつでも閉じられます。

HUNT は相手ごとのカードで「材料待ち・攻撃できる・攻撃済み・回数切れ」を表示します。攻撃できる方式のボタンから、公開材料 → 式と図 → 答えの入力 → 攻撃へ進みます。かけらは同じ世代の異なる番号、数独は同じ印の公開材料を自分で解く計算欄、シーザーは方式の必要組数、じゃんけんは過去2対戦の使い回しと今回の未開封の数字を別々に確認します。ROTATE は自分の防御として別枠にあり、無効になる未処理お題の件数を操作の近くに表示します。じゃんけんは相手の封じ待ちと開封可能を表示し、待ち中の開封ボタンは無効です。

## 何が起きているか

お題を解いて得点し、終了時の合計点を競います。各お題には計算に必要な数字、使える答え方、得点と締切が表示されます。シェアや暗号の公開を求めるお題では、公開して即答することも選べます。

シェアは秘密分散で使う「番号と値」の組です。このゲームでは秘密を 5 組のシェアへ分け、同じ世代の異なる 3 組から元の秘密を復元できます。2 組だけでは秘密を特定できません。世代は同じ秘密から作った一組を指します。

## 道具

| | やること | 代償 |
| --- | --- | --- |
| **LEAK** | シェア、または元の列と暗号の組を公開して即答 | 公開記録が相手の攻撃材料になる |
| **PROVE** | 数独の数字を付け替え、4 マスを埋めて提出 | 計算と入力が必要。誤答は減点 |
| **HUNT** | 相手の公開情報から秘密・鍵・手を計算して攻撃 | 秘密・数独・手の誤答は減点と回数消費。暗号鍵の誤答は拒否のみ |
| **ROTATE** | 秘密と鍵を作り直し、次の世代へ移る | 秘密に紐づく未回答のお題は無効・減点。じゃんけんは継続 |
| **HINT** | いま選んでいる ORDER の解き方を 1 段ぶん開く | 得点が減る。解けなくても戻らない |

通常のお題では計算の正解が +30 点、LEAK が +10 点、期限切れが −15 点です。使える答え方と実際の得点は各カードで確認します。

## 暗号の技術と、このゲームで追う計算

| お題 | 技術 | この教材で追う部分 |
| --- | --- | --- |
| 暗号文のまま足す | **準同型暗号** | 復号前の加算と、復号後の結果の対応 |
| 覆面つき小計 | **秘密計算 (MPC)** | 秘密の入力にマスクを加え、合計で打ち消す計算 |
| PROVE | **ゼロ知識証明 (ZK)** | 数独の付け替えと、一部の確認で示せる性質 |

ZK は答えを明かさず正しさを示す技術です。数独はその考え方を追う題材で、このゲームの審判は元の解を知っています。FHE は加算と乗算を組み合わせて計算できます。このお題は小さい数で加算を追うモデルです。実用方式との差は「暗号を図と式で見る」で確認できます。

## ゲームの目的

各チームの秘密は 5 組のシェアに分かれ、同じ世代の異なる 3 組がそろうと復元できます。

- 相手が3種類を公開したら、計算して **HUNT** を狙う。
- 自分の公開が危なくなったら **ROTATE** して新しい世代へ移る。
- 得点しながら、自分の現行世代を復元されないようにする。

同じ番号を何度公開しても 1 種類です。異なる世代のシェアは混ぜられません。

## ORDER は5分ごとにまとめて届く

最初は 1 件、1 分後に最初の 6 件が届き、その後は 5 分ごとに届きます。通常のお題の締切は 5 分、急ぎのお題は 2 分 30 秒です。締切前にどれを解くか、公開して答えるか、相手の情報から攻撃するかを選びます。

## ORDER の種類

| カードの依頼 | 画面で行うこと |
| --- | --- |
| share を出す | LEAK または PROVE |
| 解を見せずに示す | PROVE: 未使用の付け替え表で数独の解を書き換え、聞かれた 1 行を開く |
| 自分の鍵で暗号にする | 記号を鍵の数だけ後ろへずらして提出 (CIPHER)、または LEAK |
| 暗号文のまま足す | 2つの組を成分ごとに足し、p で割った余りを提出 |
| 覆面つき小計 | 自分の数 + 受信マスク - 送信マスクを p で割った余りを提出 |

カードには期限、得点、依頼内容、使える方法が表示されます。カードにない方法は、その仕事または公開条件を満たしません。

## 操作

| 操作 | 意味 |
| --- | --- |
| LEAK | ORDER の答えをシステムに出させて完了。何が公開されるかは ORDER による |
| PROVE | 4×4 数独の解を新しい付け替え表で書き換えて 1 行だけ開く。share は公開されない |
| CIPHER | 記号列を自分の鍵で暗号化して提出。何も公開されない |
| FHE | 暗号文を復号せずに加算 |
| MPC | 各拠点の値を隠したまま合計用の小計を提出 |
| HUNT | 公開情報から復元した secret、付け替え表の再利用から復元した数独の解、または暗号鍵を提出 |
| ROTATE | secret と share を新しい世代へ更新 |
| HINT | 選んでいる ORDER のヒントを次の 1 段まで開く。何も公開されない |

## 詰まったら — HINT

どの ORDER にも**ヒントが 3 段**あります。1 段目は「どこを見るか」、2 段目は
「使う式」、3 段目は「最初の 1 手」。3 段目まで開いても計算はあなたがやります。

開くたびに得点が減り、値段は段が上がるほど高くなります (**-2 / -4 / -8**)。ボタンに
値段が書いてあるので、押す前に見比べられます。

**全部開いてから計算しても、パスするより点は残ります。** ただし減点は ORDER を
解けなくても戻りません。捨てるつもりの ORDER にヒントを買うのがいちばん損です。

ヒントは公開記録に載りません。買ったことは相手に分かりません。

## 暗号の梯子

「自分の鍵で暗号にする」ORDER には**段**があります。段ごとに違うのは 1 つ、
**何組公開すると鍵が割れるか**です。

| 段 | 鍵が割れる公開数 | 割り方 |
| --- | --- | --- |
| シーザー | 1 組 | 暗号文 − 平文。引き算 1 回 |

方式は ORDER に書いてあります。隠していません。**秘密は鍵だけ**で、これは実際の
暗号の大原則そのものです。全チームが方式を知っていても、鍵を漏らさないチームは
狩られません。

LEAK すると平文と暗号文が**対で**公開されます。シーザーの段では、その 1 組が
そのまま鍵です。公開記録には「いま何組出ているか / 何組で割れるか」が並ぶので、
相手が既に割れているかどうかは見れば分かります。

ROTATE すると鍵も新しい世代のものになり、それまでに公開した対は役に立たなくなります。

PROVE と HUNT の式、定数、実行可能な Python は Portal の完全なルール内にあります。PROVE はヘルプが手計算で追う 4×4 数独の付け替え、シェアからの HUNT は Shamir のしきい値秘密分散です。`ac26-w2-secret-sharing` の足し算による秘密分散とは方式が異なります。

## 画面の読み順

「準備完了」を押します。全チームが準備完了になると試合が始まり、お題が届きます。

1. **いまのお題** — 何を求められているかと残り時間
2. **答え方と入力欄** — 得点・公開リスクを比べ、同じカード内で答える
3. **結果** — 回答エリアの上に得点と結果を表示
4. **秘密の公開状況・公開記録・保管庫** — 概要を見て、必要な情報を開く
5. **遊び方・図と式・穴埋め・ルール一覧** — 盤面の上から目的を一つ選んで開く

「相手を攻撃する（HUNT）」には相手ごとの公開材料と攻撃状態を常時表示します。材料がそろった方式から計算欄を開き、式・図・公開値を使って自分で答えを求めて提出します。ROTATE は防御の別枠です。

## データ境界

- match secret と完全な match state は TenkaCloud の trusted 側だけに置く。
- ブラウザは必ず `projectForTeam` の結果だけを受け取る。
- 自チームの vault と ORDER は自チームだけに見せる。
- 相手の未公開 share、secret、match secret は投影しない。
- Public Ledger に出すのは、参加者が公開を選んだ artifact だけ。

本番の隠し値はサーバー専用 `matchSecret` から導出します。`eventId` は公開情報なので使いません。ローカルだけは `local-play-not-secret:<eventId>` という明示的な非secret fallbackを使います。

## 手を隠して、相手とじゃんけん

お題が届いたら、手 m（1=グー、2=チョキ、3=パー）と隠す数 r を選びます。
r は毎回 0〜10 のくじから引き直し、手と一緒に紙へ控えます。
画面の表から 4^m と 9^r をそれぞれ 23 で割った余りを読み、掛けて **23 で割った余り**を
「封じる数字」へ入力します。例えば m=1、r=1 なら 4×9=36、36−23=13 です。

両者の数字がそろったら、控えた手と r を「手を審判へ渡す」で提出します。
審判が検算し、両方の開封をそろえて同時公開します。勝ち +30、引き分け +10、負け 0。
間違った開封は減点なしで修正できます。受理された数字・開封は変更できません。
相手待ちの間はほかのお題へ進めます。期限に自分の必要な操作を終えていれば不戦勝、
未操作なら通常の期限切れ減点です。ROTATE してもじゃんけんは続きます。

これは commit-reveal（先に封じて後で開く）の教材です。小さい数では別の手への
開け方も探せるため、暗号だけの実用的な安全性はありません。同時公開を守る審判を
信頼します。commit-reveal 自体はゼロ知識証明ではありません。得点を変えない解説と任意の
穴埋め練習で、計算とその理由を順番に確かめられます。

## 相手のじゃんけんの手を予測する

相手の過去 2 回の公開記録で、隠す数 r が同じだった場合に使える作戦です。
「公開記録からできる次の作戦」を開くと、2 回の記録・今回封じた数字 c・計算表が並びます。
今回も同じ r だと仮定して、グー・チョキ・パーのそれぞれで c を計算し、
一致する手を選んで「予測を審判へ預ける」を押します。過去の使い回しは、今回も同じという保証ではありません。

見本：r=1 の表の値は 9。グーは 4×9=36→余り13、チョキは16×9=144→余り6、
パーは18×9=162→余り1（割る数は23）。今回の c=6 ならチョキと予測できます。

相手が開封する前に 1 対戦につき 1 回送れます。予測は変更できず、相手にも見えません。
両者の手が公開されてから、的中なら +25 点、外れなら −8 点（得点の下限は0）です。
試行回数は、かけらから秘密を復元する HUNT と共通で、相手の同じ世代に合計3回まで。
時間切れで手が公開されなければ採点せず、その1回を返します。
ROTATE 後も過去のじゃんけんの公開記録と、預けた予測は残ります。

得点が確定したお題の正解には、短い演出・獲得点・現在の合計を表示します。演出が終わっても結果は残り、動きを減らす設定では演出を省きます。PROVE の誤答は減点を表示します。付け替えの図は選んだ表と左右の数独を結び、任意の解説では ZK の考え方と審判を信頼する教材モデルを区別します。

### 得点履歴の連携

PROVE、CIPHER、LEAK、FHE、MPC、DUEL、HUNT、ヒント、ROTATE、期限切れの採点理由を、秘密や回答を含まない固定コードで TenkaCloud に渡します。TenkaCloud #3194 の対応版では、参加者の「スコアイベント」で実際の増減を確認できます。減点は 0 点の下限を適用した差分です。過去に記録されなかった履歴は復元しません。
