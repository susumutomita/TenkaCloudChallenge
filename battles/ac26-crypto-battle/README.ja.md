# 暗号バトル

ヒントは選んだ1題を読んで計算・提出してから、次のお題へ進みます。シーザーの3段と、かけらのお題の最終手順をこの流れに整理しました。新規試合の回答期限は60秒です。ヒント料金は各ボタンに表示します。検証範囲と未確認事項は[読解確認記録](dev/HINT-READING.md)に記載します。

盤面の上には「遊び方」「暗号を図と式で見る」「一桁の穴埋めで練習」「ルール一覧」の入口を表示します。どれも任意です。別のスクロール領域で開き、閉じると元のお題・入力・スクロール位置へ戻ります。開いている間も開始済みの試合の時間は進みます。練習は余り → 秘密分散 → 復元 → 公開の危険 → MPC・ZK・FHE・シーザー・じゃんけんを小さい数字で追います。入力せずに読み進めることもできます。
解説は「今やること・式・1個の空欄」を先に表示し、計算の手順と理由は折り畳みから読めます。答えを確認した後も、要点は1文です。

盤面は「いまのお題 → 答え方と得点・公開リスク → 回答」にまとめます。MPC は足す覆面の合計・引く覆面の合計・自分の数への足し引き・余りへの変換を、実際の数字で表示します。結果は回答エリアの上へ表示します。ヒント、公開状況、公開記録、保管庫は必要なときに開きます。

お題一覧は回答中も表示し、未処理件数・種類・締切・選択中を確認できます。カードは締切順で、クリックまたは Tab と Enter / Space で直接選べます。新しいお題は短い到着通知とカードの「到着」で知らせ、選択や入力途中の回答は変えません。「締切間近」「期限切れ」「完了」は文字でも区別します。直近の結果を一覧の下へ残し、この画面で確認した回答の獲得点を表示します。狭い画面や件数が多い場合は一覧内をスクロールできます。

「暗号を図と式で見る」から、割った余り・秘密分散・MPC・ZK・FHE・シーザー暗号を各 4〜5 ステップで読めます。何をしたいか、仕組み、一桁の計算例、今の入力欄の順に進みます。MPC・FHE・シーザー暗号は入力欄の直前からも開け、最後にその Order の数字を使った未計算の式を表示します。解説は得点や試合状態を変えず、いつでも閉じられます。

HUNT は相手ごとのカードで「材料待ち・攻撃できる・攻撃済み・回数切れ」を表示します。攻撃できる方式のボタンから、公開材料 → 式と図 → 答えの入力 → 攻撃へ進みます。かけらは同じ世代の異なる番号、数独は同じ印の公開材料を自分で解く計算欄、シーザーは方式の必要組数、じゃんけんは過去2対戦の使い回しと今回の未開封の数字を別々に確認します。ROTATE は自分の防御として別枠にあり、無効になる未処理お題の件数を操作の近くに表示します。じゃんけんは相手の封じ待ちと開封可能を表示し、待ち中の開封ボタンは無効です。

## 何が起きているか

お題を解いて得点し、終了時の合計点を競います。各お題には計算に必要な数字、使える答え方、得点と締切が表示されます。シェアや暗号の公開を求めるお題では、公開して即答することも選べます。

シェアは秘密分散で使う「番号と値」の組です。このゲームでは秘密を 5 組のシェアへ分け、同じ世代の異なる 3 組から元の秘密を復元できます。2 組だけでは秘密を特定できません。世代は同じ秘密から作った一組を指します。

## 道具

| | やること | 代償 |
| --- | --- | --- |
| **LEAK** | シェア、または元の列と暗号の組を公開して即答 | 公開記録が相手の攻撃材料になる |
| **PROVE** | Schnorr方式で a を送り、届いた e から応答 z を手計算 | 計算と入力が必要。誤答は減点 |
| **HUNT** | 相手の公開情報から秘密・鍵・手を計算して攻撃 | 秘密・数独・手の誤答は減点と回数消費。暗号鍵の誤答は拒否のみ |
| **ROTATE** | 秘密と鍵を作り直し、次の世代へ移る | 秘密に紐づく未回答のお題は無効・減点。公開専用のお題に回答済みなら最低1問分の失効点（大きい方だけを減点し、得点は0点で止まる）。じゃんけんは継続 |
| **HINT** | いま選んでいる ORDER の解き方を 1 段ぶん開く | 得点が減る。解けなくても戻らない |

通常のお題では計算の正解が +30 点、LEAK が +10 点、期限切れが −15 点です。使える答え方と実際の得点は各カードで確認します。

## 暗号の技術と、このゲームで追う計算

| お題 | 技術 | この教材で追う部分 |
| --- | --- | --- |
| 暗号文のまま足す | **準同型暗号** | 復号前の加算と、復号後の結果の対応 |
| 覆面つき小計 | **秘密計算 (MPC)** | 秘密の入力にマスクを加え、合計で打ち消す計算 |
| PROVE | **ゼロ知識証明 (ZK)** | Schnorrの公開検証・模擬会話・知識の抽出 |

ZK は答えを明かさず正しさを示す技術です。新しい試合ではSchnorr方式を使い、秘密xは端末内に残します。保存済みの旧試合は、元の解を知る審判に頼る数独模型を維持します。FHE は加算と乗算を組み合わせて計算できます。このお題は小さい数で加算を追うモデルです。実用方式との差は「暗号を図と式で見る」で確認できます。

## ゲームの目的

各チームの秘密は 5 組のシェアに分かれ、同じ世代の異なる 3 組がそろうと復元できます。

- 相手が3種類を公開したら、計算して **HUNT** を狙う。
- 自分の公開が危なくなったら **ROTATE** して新しい世代へ移る。
- 得点しながら、自分の現行世代を復元されないようにする。

同じ番号を何度公開しても 1 種類です。異なる世代のシェアは混ぜられません。

## ORDER は30秒ごとに1件届く

新規試合は最初に1件、その後は30秒ごとに1件届きます。通常・急ぎとも回答期限は60秒です。進行中の既存試合は保存済みの設定を保ちます。締切前にどれを解くか、公開して答えるか、相手の情報から攻撃するかを選びます。

## ORDER の種類

| カードの依頼 | 画面で行うこと |
| --- | --- |
| share を出す | LEAK または PROVE |
| share を公開せよ (公開が条件) | LEAK のみ、満額。新しい番号なら公開数が 1 個増え、同じ番号なら増えない。公開を避けるなら先に ROTATE |
| 解を見せずに示す | PROVE: aを固定し、検証者のeに対する応答zを計算 |
| 自分の鍵で暗号にする | シーザー／Vigenère／Rotorの式で計算して提出 (CIPHER)、または LEAK |
| 公開鍵で数を暗号化する | 元の数mをe回掛け、nで割った余りを1個提出 (CIPHER)、または LEAK |
| 暗号文のまま足す | 2つの組を成分ごとに足し、p で割った余りを提出 |
| 覆面つき小計 | 自分の数 + 受信マスク - 送信マスクを p で割った余りを提出 |

カードには期限、得点、依頼内容、使える方法が表示されます。カードにない方法は、その仕事または公開条件を満たしません。

## 操作

| 操作 | 意味 |
| --- | --- |
| LEAK | ORDER の答えをシステムに出させて完了。何が公開されるかは ORDER による |
| PROVE | Schnorrの公開値yと会話(a,e,z)を公開。秘密xと乱数r、シェアは送信しない |
| CIPHER | お題の式で暗号化して審判へ非公開提出。RSAは公開鍵n/eを使う |
| FHE | 暗号文を復号せずに加算 |
| MPC | 各拠点の値を隠したまま合計用の小計を提出 |
| HUNT | 公開情報から復元した secret、付け替え表の再利用から復元した数独の解、または暗号鍵を提出 |
| ROTATE | secret と share を新しい世代へ更新 |
| HINT | 選んでいる ORDER のヒントを次の 1 段まで開く。何も公開されない |

## 詰まったら — HINT

どの ORDER にも**ヒントが 3 段**あります。1 段目は「どこを見るか」、2 段目は
「使う式」、3 段目は「最初の 1 手」。3 段目まで開いても計算はあなたがやります。

開くたびに得点が減り、値段は段が上がるほど高くなります (**-2 / -4 / -8**)。ボタンに
値段が書いてあるので、押す前に見比べられます。

**全部開いてから計算しても、パスするより点は残ります。** ただし減点は ORDER を
解けなくても戻りません。捨てるつもりの ORDER にヒントを買うのがいちばん損です。

ヒントは公開記録に載りません。買ったことは相手に分かりません。

## 暗号の梯子

通常の暗号お題は開始直後のシーザー、中盤の通常枠でVigenèreとRotorを交互、終盤のRSAへ進みます。
段は方式と計算の違いで、安全性の順位ではありません。発行済みのお題の方式と締切は変わりません。

| 段 | 使える攻撃材料 | 計算 |
| --- | --- | --- |
| シーザー | 元の列と暗号化した列1組 | 暗号文−平文の余りで鍵を復元 |
| Vigenère | 周期3の異なる鍵位置すべての公開 | 位置ごとに暗号文−平文の余りを計算 |
| Rotor | 現世代のRotorの公開組が1組以上 | 4文字の状態を追い、初期位置a・bを計算 |
| RSA | 相手の公開鍵n/e。LEAK不要 | nを異なる素数2個の積に分ける |

Vigenèreは1位置ずつの短いお題です。同じ位置の公開だけを増やしても残りの鍵は決まりません。
長い平文と暗号文が周期3をすべて含めば、その1組だけでも3位置の鍵が分かります。

RSAは元の数m=2〜9、公開n≤77、e=3・5・7の小さい教材です。式は `c=m^e mod n`、
つまりmをe回掛けてnで割った余り。途中で余りにしても結果は同じです。
別の数の例：3³を7で割るには3×3=9→余り2、2×3=6です。
新規試合は通常・急ぎとも60秒。初回正答は通常30点、急ぎのVigenèreは45点です。

CIPHERの元の数と答えは審判だけに送ります。LEAKは元mと暗号化したc、公開n/eを記録します。
形式の正しいVigenère/Rotor/RSA誤答は−6点で、そのお題の再正答は0点です。期限内に正しく完了すれば
失効を避けられます。ライトニング宣言済みでも0点は倍にして0点、誤答前の正答なら60点です。

RSAのHUNTは素数（1と自分以外では割り切れない2以上の整数）を2欄へ順不同で提出します。
成功+25点、被害−12点（0点未満にはしない）。因数から元に戻す鍵を計算できる理由は
画面の任意解説でφ・dとn=33の復号例を追えます。内部dとの一致は要求しません。
因数の誤答は拒否のみで、同じ相手・世代への成功は1回です。

ROTATEは秘密と鍵を次の世代へ更新しますが、小さいRSAの同じnが再登場する場合があり、
公開鍵だけからの因数分解を防ぐ保証はありません。実用RSAには大きい鍵と乱数を含む符号化が必要です。
RSAの公開／非公開鍵の役割はセミナーWeek5のスライド3〜4、計算はRFC 8017のRSAを小さい数で追います。
[参加者の読み取りと実画面の記録](dev/RSA-READING.md)に確認範囲を示します。
Rotorの模型は以下のとおりです。暗号文を加算する既存のお題も全フェーズで続きます。

PROVE と HUNT の式、定数、実行可能な Python は Portal の完全なルール内にあります。新しい試合のPROVEは下記のSchnorr方式、シェアからの HUNT は Shamir のしきい値秘密分散です。`ac26-w2-secret-sharing` の足し算による秘密分散とは方式が異なります。

## 画面の読み順

「準備完了」を押します。全チームが準備完了になると試合が始まり、お題が届きます。

1. **いまのお題** — 何を求められているかと残り時間
2. **答え方と入力欄** — 得点・公開リスクを比べ、同じカード内で答える
3. **結果** — 回答エリアの上に得点と結果を表示
4. **秘密の公開状況・公開記録・保管庫** — 概要を見て、必要な情報を開く
5. **遊び方・図と式・穴埋め・ルール一覧** — 盤面の上から目的を一つ選んで開く

「相手を攻撃する（HUNT）」には相手ごとの公開材料と攻撃状態を常時表示します。材料がそろった方式から計算欄を開き、式・図・公開値を使って自分で答えを求めて提出します。ROTATE は防御の別枠です。

## データ境界

- match secret と完全な match state は TenkaCloud の trusted 側だけに置く。
- ブラウザは必ず `projectForTeam` の結果だけを受け取る。
- 自チームの vault と ORDER は自チームだけに見せる。
- 相手の未公開 share、secret、match secret は投影しない。

## 手を隠して、相手とじゃんけん

お題が届いたら、手 m（1=グー、2=チョキ、3=パー）と隠す数 r を選びます。
r は毎回 0〜10 のくじから引き直し、手と一緒に紙へ控えます。
画面の表から 4^m と 9^r をそれぞれ 23 で割った余りを読み、掛けて **23 で割った余り**を
「封じる数字」へ入力します。例えば m=1、r=1 なら 4×9=36、36−23=13 です。

両者の数字がそろったら、控えた手と r を「手を審判へ渡す」で提出します。
審判が検算し、両方の開封をそろえて同時公開します。勝ち +30、引き分け +10、負け 0。
間違った開封は減点なしで修正できます。受理された数字・開封は変更できません。
相手待ちの間はほかのお題へ進めます。期限に自分の必要な操作を終えていれば不戦勝、
未操作なら通常の期限切れ減点です。ROTATE してもじゃんけんは続きます。

これは commit-reveal（先に封じて後で開く）の教材です。小さい数では別の手への
開け方も探せるため、暗号だけの実用的な安全性はありません。同時公開を守る審判を
信頼します。commit-reveal 自体はゼロ知識証明ではありません。得点を変えない解説と任意の
穴埋め練習で、計算とその理由を順番に確かめられます。

## 相手のじゃんけんの手を予測する

相手の過去 2 回の公開記録で、隠す数 r が同じだった場合に使える作戦です。
現在のじゃんけん回答欄に、任意の予測フォームと、2 回の公開記録・今回封じた数字 c・計算表が並びます。
今回も同じ r だと仮定して、グー・チョキ・パーのそれぞれで c を計算し、
一致する手を選んで「予測を審判へ預ける」を押します。過去の使い回しは、今回も同じという保証ではありません。

見本：r=1 の表の値は 9。グーは 4×9=36→余り13、チョキは16×9=144→余り6、
パーは18×9=162→余り1（割る数は23）。今回の c=6 ならチョキと予測できます。

両者の手が公開される前まで、1 対戦につき 1 回送れます。相手だけが手を審判へ預けた段階も受付中です。
預かり中の手や r は見えません。予測してから自分の手を開くことも、予測せず回答を続けることもできます。
予測は変更できず、相手にも見えません。毎回くじを戻して引けば、偶然同じ r になることもあります。
手と r を毎回独立に等確率で選ぶ相手なら、候補と照合できた後も的中率は3分の1です。
両者の手が公開されてから、的中なら +25 点、外れなら −8 点（得点の下限は0）です。
試行回数は、かけらから秘密を復元する HUNT と共通で、相手の同じ世代に合計3回まで。
時間切れで手が公開されなければ採点せず、その1回を返します。
ROTATE 後も過去のじゃんけんの公開記録と、預けた予測は残ります。

得点が確定したお題の正解には、短い演出・獲得点・現在の合計を表示します。演出が終わっても結果は残り、動きを減らす設定では演出を省きます。PROVE の誤答は減点を表示します。付け替えの図は選んだ表と左右の数独を結び、任意の解説では ZK の考え方と審判を信頼する教材モデルを区別します。

### 得点履歴の連携

PROVE、CIPHER、LEAK、FHE、MPC、DUEL、HUNT、ヒント、ROTATE、期限切れの採点理由を、秘密や回答を含まない固定コードで TenkaCloud に渡します。TenkaCloud #3194 の対応版では、参加者の「スコアイベント」で実際の増減を確認できます。減点は 0 点の下限を適用した差分です。過去に記録されなかった履歴は復元しません。

### 終盤のヒント支援（#659 のブースター）

終盤に入る時点で最下位のチームは、そこから10分間、ヒントを開いても減点されません。同点最下位は全員が対象です。1チームの練習は対象外です。配布と同時に有効になり、後の順位変動・再読込・鍵の更新で対象や終了時刻は変わりません。通常設定では試合開始60分後に配布し、70分後に通常の減点へ戻ります。試合終了が早ければ支援もそこで終わります。

画面の「ヒントの減点なし · 残り …」と次のヒントの減点を確認し、選んだお題のヒントを開いて計算を続けます。お題の期限、配布間隔、回答の得点は変わりません。送信中に支援が終わって表示時の減点と変わった場合は、開かずに更新を案内します。

旧版から終盤開始後に引き継いだ試合では、その時点の順位が記録されていないため、過去の配布を推定せず通常の減点を維持し、画面にも理由を表示します。上位暗号への段階進行は別の変更です。ライトニングは下記のルールで動作します。

## 暗号の梯子：シーザー・Vigenère・Rotor・RSA

暗号のお題は、既存の pressure フェーズ（既定では試合開始30分後）から
新しい段で届きます。配布済みのお題の方式・締切は変わりません。
build は鍵1個のシーザー、pressureの通常枠はVigenèreとRotorが交互、
endgameの通常枠はRSAです。急ぎの暗号お題はVigenèreを保ちます。Vigenère
（ヴィジュネル）は鍵3個を繰り返します。強調された鍵の位置を読み、元の番号にその鍵を足し、
6で割った余りを1個入力して **CIPHER** で提出します。答えは信頼する審判だけへ
送り、公開しません。本物のゼロ知識証明を行う操作ではありません。

Vigenère は鍵1→鍵2→鍵3→鍵1と繰り返します。このゲームでは各お題を
その1位置だけに切り分けています。LEAK は元の番号・答え・鍵の位置を公開します。
異なる3位置が揃うと全鍵が分かります。サーバーも対象チーム・段・現世代の3位置を必須にします。同じ位置を3件集めても揃いません。
攻撃画面で公開された位置を確認し、引き算で戻した鍵1・2・3を空白区切りで入力します。
3位置をすべて含む長い平文と暗号文を1組公開すれば、その1組だけで全鍵が分かります。
鍵を繰り返すこの古典暗号には、現代の実用暗号の安全性はありません。

CIPHER の初回正解は通常のお題30点（既存の rush 設定ではその加点）です。
Vigenère・Rotor・RSA の形式が正しい誤答は既存の `wrongProve`（通常6点）を減点し、
そのお題の以後のCIPHER報酬は0点になります。正しく解き直せば完了し、期限切れ
減点を避けられます。未入力・範囲外は誤答に数えません。画面に提出前から表示します。
LEAK は引き続き10点、
Vigenère の HUNT は攻撃側25点・相手12点減点です。減点は0点で止まります。
シーザーの HUNT は既存の8点を維持します。ROTATE 後も公開記録は残りますが、
古い世代の鍵による攻撃は受理されません。AWS の追加リソース・設定・タイマー・
削除作業はありません。

ローカル検証：game で `bun test && bun run typecheck`、dev で
`bun test && bun run typecheck`。dev の `vigenere` シナリオは通常の5分TTLを使い、
相手の実際のLEAK操作3回で公開記録を作ります。[画面と計算の記録](dev/VIGENERE-READING.md)。
RSA は終盤の通常のお題と公開鍵からの HUNT として実装済みです。
Rotorは以下の2輪模型です。既存の準同型加算のお題を別の新規方式に置き換えません。
既存の秘密分散・暗号文の加算・終盤のヒント支援は引き続き利用できます。


### 終盤のライトニング（#659 §9）

既存の終盤境界で下位2チームへ1枚ずつ配ります。下から2番目のチームと同点の
チームまで全員対象です。2チーム戦は最下位のみ（同点なら両方）、1チーム練習は
対象外です。ヒント支援と同じ境界時点の順位で一度だけ確定し、再読み込みや
その後の順位変化では配り直しません。カードと指定先は自チームだけに投影します。

一覧で未回答の計算のお題を選び、回答前にライトニングを指定します。
PROVE・CIPHER・FHE・MPCの正解報酬が、そのお題の既存得点の2倍になります。
rushの得点も対象です。#659のPROVEは「自分で計算して出す」の総称として扱い、
じゃんけんの勝敗・引き分け・不戦勝によるDUEL得点は計算の正解報酬と異なるため
対象外です。新しい得点定数や時間制限は追加しません。

一度指定すると取り消し・別のお題への付け替え・重ね使用はできません。
受理されたPROVE誤答やVigenère・Rotor・RSAの失敗が残るお題には後から指定できません。
従来どおり拒否される入力は、受理済み回答の履歴には数えません。
指定後の誤答は、既存期限まで同じお題で解き直せます。減点も従来どおりです。
Vigenère・Rotor・RSAは誤答で元の報酬が0になるため、2倍後も0点です。正しく完了すれば
期限切れ減点を避けられます。LEAKは通常得点で完了しカードを使い終わります。
期限・ROTATE・試合終了でも失効し、減点を2倍にすることはありません。
画面には対象のお題・正解時の得点・残り時間を並べ、別のお題を選んだときは
指定したお題へ戻るボタンを表示します。

schema 9で配布・指定・結果と受理済み回答履歴を保持します。旧版で既に終盤を
迎えた試合は当時の順位を推定せず対象外と表示します。旧版の未完了お題も回答履歴が
不明なので指定できず、新しく届くお題から対象になります。schema 8のVigenère
失敗フラグ、圧縮済みHUNT/RPS予約、ヒント支援の決定は保持します。

ローカル検証は `game/src/lightning.test.ts` の実reducer・host・Portal部品と、
通常のtickと相手の計算で61分へ進むdevの `lightning` シナリオを使います。
game/devのテスト・型検査とcatalog gateを実行します。[画面記録](dev/LIGHTNING-PLAYTHROUGH.md)。

### Rotor：進む2つの車輪を追う

通常のpressure暗号枠はVigenèreとRotorを交互に出します。Rotorは数字0〜3の4文字を、
公開表P=[1,3,0,2]、Q=[3,0,2,1]へ順に通します。自分と審判だけが初期位置a・bを知ります。
式は `u=(P[(m+a) mod 4]−a) mod 4`、`c=(Q[(u+b) mod 4]−b) mod 4`。
mod4は4で割った余り（負なら4を足す）、mは元の数字、uは途中、cは出力です。
出力してからaを1進め、aが3→0に戻るときだけbも1進めます。bも3の次は0です。
式・一桁例・4行の記入表を入力欄のそばに表示します。3つの鍵を反復して足す方式とは異なり、
位置と対応表の組で変換が変わります。同じ初期位置なら、Q→Pの表を逆に引いて元へ戻せます。

同じ世代のお題は毎回同じ初期位置から始めます。CIPHERは4文字を非公開提出して30点、
LEAKは元の列と答えを公開して10点。公開1組で初期位置を特定できる場合も、候補が残る場合もあります。
HUNTは現世代のRotor公開組1組以上と正しい初期a・bを確認し、成功25点・相手12点減点（0点で停止）。
2回のLEAKや画面側の一意性判定は要求しません。誤答は8点減点し、同じ相手・世代のシェア復元・
じゃんけん予測と共通の既存3回枠を使います。数独の別枠は変えません。
CIPHER誤答の6点減点・以後0点（ライトニングも0）、新規試合の60秒期限・30秒ごとの1問、終盤RSA・急ぎVigenèreに従います。
ROTATEは旧お題を失効させ、旧世代への攻撃を受け付けなくします。初期位置は16通りなので同じ数字が再登場し得ます。

これは実用Enigmaの再現でも、安全性の強さ順でもありません。
[NSAの教育用simulator](https://github.com/NationalSecurityAgency/enigma-simulator/blob/master/components.py)の
位置を足す→配線→位置を引く原理だけを借りています。確認した公式セミナーとownerノートには
Rotorそのものの演習はなく、暗号化と元へ戻す鍵、再利用が漏洩につながる条件を式で確かめる点を接続します。
[参加者役の読解・実採点・画面の記録](dev/ROTOR-READING.md)。新しいAWSリソース・権限・タイマー・得点値・削除作業はありません。

### 回答画面 (#780)

新しいシーザーのお題は5個の数字です。回答欄にはスペース区切りを明記します。旧試合の数独PROVEは未使用の置き換えを非公開の乱数で用意し、印のついた4入力欄をすぐ表示します。時計更新や同じ内容の再取得では置き換えは変わりません。これは引き続き審判を信頼する模型で、完全なZKプロトコルではありません。MPCは3者のマスクの相殺を図と一般式で示し、じゃんけんの累乗は上付きと掛け算の展開で表示します。

### HUNTの相手選択 (#782)

公開材料のある相手を優先して5チームずつ表示し、チーム名・ID検索と材料ありの絞り込みを用意します。相手と方法を選ぶと1つの計算欄を表示します。公開情報の更新で選択中の計算欄を勝手に切り替えません。成功した方法は現世代では攻撃済みとなり、ROTATEは別の防御操作として表示します。

### 新しい試合のゼロ知識証明（Schnorr、#783）

講義のWeek 3・スライド54〜60と学習ノートのSchnorrの節に対応します。

| 手順 | 自分の端末だけに残す | 送る・受け取る |
| --- | --- | --- |
| 準備 | 秘密 x と毎回新しい乱数 r | 公開値 y = 2ˣ mod 23 |
| 1 | r | a = 2ʳ mod 23 を手計算して固定 |
| 2 | x, r | 検証者が e（0〜10）を返す |
| 3 | x, r | z = (r + ex) mod 11 を手計算して送る |

検証者は公開値だけで **2ᶻ ≡ a yᵉ (mod 23)** を検査します。xとrはサーバーに送りません。aとyは後から変更できず、誤答を含め応答は1回限りです。別チームのお題・期限切れ・再送による二重得点を拒否します。乱数は同じタブに保存されるため、証明を開始したタブで続けます。

数学の解説では、具体例から指数法則、秘密なしで同じ分布の会話を作るシミュレータ、同じaへの2応答からxを取り出す式を順に扱います。これは正直な検証者に対するZK（HVZK）です。小さな群は全探索でき、推測した問いが当たる確率も1/11あるため、実用の安全性はありません。公開検証の成功は秘密の復元ではなく、HUNTの得点にはしません。

この主張は「yに対応する離散対数xを知る」であり、秘密分散のシェアや数独の解を知ることの証明ではありません。旧版の数独模型と新しい方式を混同しないよう、保存済み試合は従来方式のまま扱います。

公開値 y はお題ごとにサーバーが指定し、提出者は差し替えられません。小さい群の教材なので、ブラウザは表から対応する x を求めて表示します。これは実用の秘密鍵配布ではありません。検証関数は公開値だけを受け取り、応答には x・r を含めません。

### SNARK の算術化を手計算する (#791)

### iOの定義を有限入力で確かめる (#793)

新規試合では19枠ごとの通常候補にiOのお題を混ぜ、既存のEC・じゃんけんの優先枠を維持します。5で割った余りで行う3操作の計算A/Bについて、全入力0,1,2,3の表の空欄2個、機能が同じかの0/1、公開結果に共通する組の個数を提出します。既存の問題runtimeが期限・所有者・再送・得点・ライトニングを処理し、得点理由は `io` です。

根拠：Barakほか *On the (Im)possibility of Obfuscating Programs*（CRYPTO 2001、https://www.boazbarak.org/papers/obfuscate）、Jain・Lin・Sahai *Indistinguishability Obfuscation from Well-Founded Assumptions*（https://doi.org/10.1145/3785007）。同サイズ・全入力で同機能の回路を比較し、機能保存・計算量的識別不可能性・効率性を要求する定義を扱います。模型のサイズは算術操作3個であり、一般の論理回路のビット単位のサイズではありません。

全入力の答えを列挙した真理値表へ正規化し、元の式を捨てます。表の回転と公開する位置rの組を表示された候補から等確率で選び、入力xは位置(x+r) mod 4から答えを読みます。同機能で乱数の候補も同じなら分布が一致します。元の式によって候補を変える不適切な変換も出題し、同機能でも共通する組が0〜4個に変わるため、機能の一致から最後の答えを転記できません。確率の違いから元が分かる場合があり、共通する個数だけでは識別不可能性は証明できません。元のA/Bというラベルを付ければこの条件は壊れます。異なる機能はiOの識別不可能性の対象外です。暗号化でも機能そのものの秘匿でもありません。入力kビットでは2^k行が必要なため、**一般の効率的iOの実装ではありません**。引用論文の暗号構成を実装したという主張もしません。

全625表・全4回転の機能保存、1入力だけ変更した分布、同機能・異機能の生成、正誤の得点、倍率、他チーム・再送・期限拒否を検証しました。実際のローカルPortal `io-order` でA=2x、B=2(x+3)+1に対して `4 3 0 0` を入力し、成功表示と+30を確認。SNARK #797との統合後に通常回帰758件、dev79件、型検証を通過しています。保存形式17で既存試合の設定を維持します。デプロイは行っていません。

追加検証では、空でない回転候補225組について機能保存と部分的に共通する分布を確認しています。乱数候補変更後のローカルPortalでも、上記の `4 3 0 0` による成功表示と+30を確認しました。
