# 次のイベントでの参加者画面確認

この手順は、オーナーが新しいイベントを用意した後の任意リハーサルです。
デプロイ、イベント作成、既存試合のリセットを実行する手順ではありません。
実AWSや第三者による未実施を、開発PRのマージ条件にはしません。

現在の基準は `p=97`、数独の4マス穴埋め、上部の任意解説、3段ヒント、
HUNTの誤答減点と共有予算です。「2桁」は0〜96の意味で、1桁も正常です。
MPC/FHEの入力は0〜96です。任意解説のMPC/FHEの見本では7で割ります。
解説は自動表示を要求せず、盤面より上のボタンから任意に開けることを確かめます。

## 先にローカルで確認する

[dev/README.md](README.md) のコマンドで実Portal部品を起動します。SCENARIOとSEATは
ローカル専用の準備操作です。答えを求めるときは参加者画面の説明・記録・
無料の計算表だけを読み、生の試合データやソースの参照解は開きません。

| 項目 | SCENARIO | 画面での操作と合格条件 |
| --- | --- | --- |
| 1. 任意解説 | `waiting` / `fresh` | 盤面の上に「この問題の解説」と「順番に解説を読む（任意）」がある。開くと短い指示・式・空欄が出る。未回答でも次へ進め、閉じるとお題に戻れる。 |
| 2. チーム名 | `ledger-filling` | 「秘密の公開状況」と「公開記録と自分の保管庫」を開く。alpha / bravoが表示される。ローカルではULIDを名前に直す本番側の処理は確認できない。 |
| 3. 最初のお題 | `fresh` | 最初のかけらのお題のヒントを3段開く。「かけらは秘密から作った数。必要な個数で戻せる」と自分の言葉で説明できる。LEAKで10点が増え、公開した番号が記録に残る。試合開始から60秒まで時計を進めると次のバッチが出る。 |
| 4. FHE | `fhe-order` | 「いまのお題」に切り替える。左右どうしを足し、画面の割る数で余りにして提出。3段目のヒントがそのお題の数を使い、成功と得点が見える。 |
| 5. MPC | `mpc-order` | 自分の数＋受け取った数−送った数を、画面の段階入力で計算する。負なら割る数を足す。3段目が自分の数を使い、提出成功と得点が見える。 |
| 6. 数独 | `fresh` | PROVEを開き、付け替え表を選ぶ。見本12マスと自分で埋める4マスがある。矢印に従って紙で作った4個を入力し、成功・得点と公開された一部分を確認する。 |
| 7. HUNT誤答 | `hunt-reachable`、bravo席 | alphaの公開された3個から画面の式で秘密を復元し、その値と異なる余りを提出する。「外れ」、減点、残り2回を見る。得点0では減点後も0が正常。 |
| 8. 再提出 | 項目7の続き | 同じ誤答を再送し、2回目のバナーと残り1回を見る。3回目の後は送信できない。シナリオを再選択すると練習が初期化されるので、途中では切り替えない。 |
| 9. PortalのScore/Rank | ローカル対象外 | 本番Portalでのみ下の手順を行う。ローカルのスコア表示をPortal全体の更新の証拠にしない。 |

追加の対戦確認は `rps-reuse` で行えます。公開記録の同じ隠す数と無料の表から
相手の手を予測して預け、両者の開封前は未採点、開封後は勝敗と予測の点数を
別に確認します。時間切れの場合は手が公開されず、予測回数が返ります。

## 新イベントで確認する

オーナーが用意した2チーム以上の参加者ログインを別々のブラウザで開きます。
上の項目1〜8を同じ順で行い、時計の操作は実際の経過時間に置き換えます。
FHE/MPCは「ほかのお題を選ぶ」から選択し、各画面の割る数と入力を使います。

- チーム名はイベントに設定した名前と照合します。先にtickが初期化したイベントでも、危険度と公開記録にULIDが残っていないことを確認します。
- 初回LEAK後の次バッチは、試合開始から60秒の配布にポーリング時間を加味して観測します。操作から60秒を再起算しません。
- HUNT用の材料は、別チームで同じ世代の異なる番号を3個公開して用意します。同じ番号の再公開を3個と数えません。
- Score eventsで「最新の履歴に更新」を押し、直前の得点イベントとヘッダーのScore/Rankが更新されることを確認します。順位は相手の点も踏まえて照合します。

古い試合状態を疑う場合は、オーナーに新イベントでの再現を依頼します。
既存試合を勝手にリセットしません。試合の作り直しと記録の保持は
[TenkaCloud #3153](https://github.com/susumutomita/TenkaCloud/issues/3153)で追跡しています。
このIssueは設計の追跡先で、リセットを実行する手順ではありません。
チーム名は[#3190](https://github.com/susumutomita/TenkaCloud/issues/3190)、
ヘッダー更新は[#3185](https://github.com/susumutomita/TenkaCloud/issues/3185)の確認対象です。
