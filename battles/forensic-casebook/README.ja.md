# フォレンジック調査室 — 証拠で結論を支える

侵入後に残った記録を調べる、日英対応の4ケース教材です。フォレンジックとは、
記録や保存物を保全し、何が起きたかを証拠から調べることです。
TenkaCloud のネイティブ coordination host で採点でき、ローカル練習画面も備えます。
登場する組織・人・アカウント・通信先・日時・記録は全て合成です。
実在の事件を再現したものでも、事件や人物についての事実の主張でもありません。

## 担当する役割と最初の一手

架空の Aster で、外部書き出しの設定が変わりました。あなたは調査担当です。
まず `identity.json` を開き、`account`（アカウント名）と `session`
（ログイン後の操作を結ぶ番号）を探します。同じ session を操作ログと結び、
**結論と、それを支える最小限の証拠ファイル**を一緒に提出します。
答えだけが正しくても合格しません。無関係なファイルを追加した引用も不正解です。

同じ出来事と権限を、次の順で調べます。

1. **認証は通った。変更は許可されていた？** 認証成功、技術上の権限、
   業務としての承認、操作した人について言えることを区別します。
2. **何が、いつ、どこまで出た？** 時差をそろえ、別々の記録を結びます。
   ファイルを読めたことと外部に届いたことを分け、内容指紋の不一致や
   重なる受領範囲を見抜きます。記録の穴は不明として残します。
3. **バックアップがある。戻せる証拠は？** 本番と複製に共通する管理権限を
   調べ、分離して管理され、実際に復元できたコピーを選びます。
   試験環境での復元と本番の業務再開を区別します。

既存3ケースは各20・30・50点の3問、合計300点です。端末ケースは6問100点
（模擬再起動は0点）、全15問で最大 **400点**。合言葉の探索や攻撃対象はなく、実際のサービスを
変更する必要もありません。

## ローカルで遊ぶ

Bun 1.3.11、または互換性のある Bun を用意し、このディレクトリで実行します。

```sh
make install
make dev
```

表示された座席の完全なリンクを開きます。接続先は `127.0.0.1:5668` だけです。
リンクには毎回生成される座席の認証情報が含まれるので公開しないでください。
実際の `portal/StatusPanel.tsx` を使う画面が開きます。初期表示は日本語で、
英語にも切り替えられます。証拠を読む、必要ならJSONを保存する、答えを入力する、
引用するファイルを選ぶ、送信する、という流れです。

誤答時は入力が残り、試行回数が増えます。正答値を漏らさない共通の案内を返し、
減点なしで再挑戦できます。各問の無料ヒントは、仕組み→小さな例→手元の証拠を
使う手順の3段階です。正解した後も順に開けます。正解すると日英の解説が開きます。
送信結果を受け取れなかった場合も、同じ操作番号で安全に再送し、二重加点を防げます。

練習だけに「新しい練習を始める」があります。別の確認操作を経て、新しい
サーバー秘密値・試合番号・世代で証拠を作り直し、その座席の得点を0にします。
他の座席は変わりません。古い世代の遅延した操作は拒否します。
**本戦の参加者操作にリセットはありません。** 練習点数は本戦の順位に使いません。
ケースは任意の順に解けますが、表示順が推奨の学習順です。

詳しい操作と検証方法は [ローカル練習ガイド](dev/README.md) にあります。

## 証拠と保全

12個のJSON証拠ファイルを、サーバーだけが持つ `matchSecret` と、試合・チーム・
世代・用途の名前から HMAC-SHA-256 で生成します。HMAC は秘密の鍵を使って値を
導く方法です。公開された試合番号だけから同じ素材を作る代替経路はありません。
同じ練習中は証拠が安定し、別チームや新しい練習では異なる素材になります。

各ファイルのSHA-256は、末尾の改行も含むUTF-8の内容を比較する指紋です。
保存後に照合すれば、配布されたバイト列が変わっていないか確認できます。
ただし、その一致だけで元の出来事が本当だったか、誰が操作したかは証明しません。
収集範囲や由来の説明に、この教材で分かる範囲と分からない範囲を記載しています。

必要な用語、時刻の計算、受領範囲の扱い、回答形式は無料で表示します。
例えば `12:00+09:00 = 03:00Z`。範囲 `[0,3)` と `[2,5)` は重なりを1回だけ数え、
全体で5バイトです。操作番号と内容指紋の**両方**が一致して初めて、受領をファイルに
結び付けます。外部製品の知識や暗号の計算は前提にしません。

## サーバー採点の契約

`coordination/plugin.ts` はSDKへの独立した依存を持たない、構造的なプラグイン
オブジェクトを公開します。関数は `initialState`、`validateOp`、`applyOp`、
`projectForTeam`、`teamScores`、状態版は `stateSchemaVersion: 1` です。
本体側のネイティブhostへの明示的な登録が必要です。メタデータが形式上正しいだけで
実行対応済みとは言えません。runtimeはhost既存の `local / bun` 表現を使います。

- 初期化には試合番号、重複のない1〜100チーム、32〜128文字のASCII秘密値が必要です。
  秘密値は16進数やbase64として扱える表現で、参加者ではなくhostが生成します。
- 練習の新規状態生成だけは、第2引数 `{ generation }` で世代を指定できます。
  世代は1〜1,000,000の整数です。
- 操作には種別、固有の操作番号 `id`、現在の改訂 `revision`、世代 `generation`、
  ケース・設問の番号が必要です。回答は `answer` と `evidenceIds`、ヒントは
  `rung`（1・2・3）を追加します。未知の余分な項目は拒否します。
- hostが認証済みチーム番号を渡します。入力内のチーム名を信用しません。
  形式不正や古い改訂・世代は状態を変更しません。誤答は有効な試行として受理し、
  `lastResult.status = "incorrect"` にします。
- 更新関数は元の状態を書き換えません。各チームの受理済み操作で改訂が進み、
  正解点は各問1回だけです。ヒントは得点を変えません。
- 各チームの直近64件の操作番号と内容指紋を保持します。同一の再送は何も変えず、
  同じ番号で内容を変えると拒否します。履歴から外れた古い操作も改訂で拒否します。
  世代の確認は再送判定より先です。
- 参加者への投影は公開項目だけを選び、状態本体・秘密値・正答値・必要引用集合・
  操作履歴・他チームの証拠を返しません。解説は正解後、ヒントは開いた段だけです。
  未登録チームには証拠を返しません。
- `teamScores` はhostの順位表示に現在の絶対得点を渡します。稼働時間点、初期点、
  速度ボーナス、隠れた減点はありません。同点は、hostが事前に示す別の規則がない限り
  同点です。本戦の開始・終了はhostの責任です。

回答は512文字、引用は重複なし最大4ファイル、操作番号は64文字、チームごとの
受理操作は1,000,000件までです。サーバーには秘密値と簡潔な進行だけを保存し、
証拠は毎回再生成します。飽和状態の検証で、基礎2,048バイト＋チームごと16,384バイト
という宣言内に収まり、最大100チームでも2MiB未満と確認します。
永続化、認証、本戦の開始・終了、競合する更新の安全な保存はhostの責任であり、
メモリー内のローカル練習だけから実運用の保証はしません。

## 検証

```sh
make test              # 採点ロジックと練習HTTP境界
make typecheck
make browser-test      # 実Portal部品、参加者に見える証拠だけで操作
# Chromiumがない場合:
bunx playwright-core install chromium
# インストール済みChromiumには BROWSER で実行ファイルを指定できます。
```

採点テストは8世代の既存9問と端末6問を公開証拠から解き、引用の不足・余分な引用、過大な主張、
不一致の指紋や重なる範囲を単純加算する近道、秘密値とチームと試合の分離、
入力検証、JSON保存後の復元、再送、正解後のヒント、旧世代の拒否、本戦のリセット禁止、
最大状態サイズを確認します。HTTPとブラウザのテストは練習アダプター側にあります。
ブラウザでは両言語・全問・保存・誤答・再試行・成功応答の取りこぼし・ヒント・
座席分離・確認付き練習リセット・狭い画面を確認します。独立した第三者による
プレイテストではなく、ローカルの再現可能な検証です。

2026-10-09のローカル検証：型、採点・HTTP・端末テスト、標準カタログゲートが通りました。
既存Chromeで実Portalコンポーネントの全15問を日英で実走し、証拠保存と指紋、
誤答再試行、応答取りこぼしの再送、2席の分離、確認付きリセット、390px幅を確認。
スクリーンショットは `dev/evidence/endpoint-ja.png` と `endpoint-en.png` に生成します。
実OS、実クラウド、長期観測、第三者プレイテストは未実施です。

リポジトリルートでは `make install && make agent-gate` も実行します。
これはカタログ契約の確認であり、runtime実行の証明ではありません。
本体側の登録変更では、ネイティブhostの登録・HTTP永続化・ブラウザ統合を別に検証します。
実AWSイベントやクラウド展開はこの教材のテストでは行いません。

## 構成・費用・安全・終了

- `game/`: サーバー専用の証拠生成・採点・状態更新
- `coordination/`: ネイティブhostへの入口
- `portal/`: 参加者画面。公開投影の型だけを参照
- `dev/`: 認証付き、loopback限定の練習サーバー
- `tests/`: 採点・HTTP・参加者経路の検証

EC2・S3・クラウドDB・外部通信先などは作りません。Regionの指定は不要です。
想定時間は90〜120分。使用するのはローカルのCPU・メモリーと、必要ならブラウザを
置くディスクです。別途配備されるhostには、その既存サービスの費用がありえます。
Ctrl-Cで練習プロセスを終了すると、メモリー内の練習状態と認証情報は失われます。
`dev/evidence/` の検証スクリーンショットは削除できます。この教材には終了後も
課金を続けるクラウド資源はありません。座席の認証情報、サーバー状態、運営・テスト用
素材を参加者向けのファイルとして公開しないでください。

## 追加端末ケースと互換性

「消した更新ツールが戻ってくる」では、一覧・承認・再作成履歴から診断し、変更前の元内容と
SHA-256を模擬保管します。設定停止・対象隔離・対象だけの通信停止、正常更新の復旧、
模擬再起動、観測評価の順に採点します。ファイル削除だけ、正常対象の削除、全通信停止、
根拠不足、順序違反は不合格で、模擬対処の状態は進みません。誤答も受付履歴には残ります。
再起動の成功だけで完了点は出ず、再発なしと正常更新成功を根拠付きで報告して30点です。
未収集helperは不明、1回の模擬観測を実端末の感染除去や長期安全とは扱いません。
チーム点数は個人認定に使いません。OS設定・実マルウェア・認証情報・外部通信は使いません。

状態版は2です。本体ホストは版2でmigration関数を要求するため、明示的に拒否する
`migrateState` を用意しています。版1の進行中イベントを再初期化・拡張せず、既存の固定済み
版1バンドルで続け、新版は新規イベントで使います。最大点数は400点。新しい登録や
本体ソース変更は不要ですが、本体の全HTTP永続化・配備・実イベントは今回未検証です。
