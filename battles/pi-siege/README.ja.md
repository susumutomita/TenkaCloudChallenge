# π包囲戦 — 近づく記録と、逃げ道を塞ぐ競技

相手より良い記録や保証を作り、公開された主張の穴を突く2人対戦です。1本の研究原稿から「分数で近づく」「ゼロへの逃げ道」「混ぜ方の反例」「両立する配分」の4ラウンドを作りました。各6枚の行動券を、試行・強化・公開・監査へどう配るかはプレイヤーが選びます。起動・待機では得点しません。

**AWSなしで動く日本語のローカル試作**です。TenkaCloudのカタログ・本体local hostには未登録です。[設計](DESIGN.ja.md)と[原稿・独立数学レビュー](RESEARCH.md)も参照してください。

## 遊ぶ

Bunとブラウザを使います。AWS・外部API・有料処理は使いません。

```sh
cd battles/pi-siege
make install
make dev
```

`http://127.0.0.1:5655/?team=alpha`（青席）と`http://127.0.0.1:5655/?team=bravo`（橙席）を別タブか別ブラウザで開き、両者が「準備完了」を押します。最初はp=3、q=1のまま「分数を試す」。πからの誤差の目安と1/q³との比較が返ります。式・小さい例・3段階ヒントはすべて無料です。

一手ごとに交代し、ラウンドごとに先手も交代します。券を使い切るか「行動を終える」で終了。両者が終えると公開主張を精算し、次へ進みます。券は持ち越しません。最後に勝敗、自分たちの判断、歴史的な難所、原稿の突破案、ゲーム外に残る証明と検証を振り返ります。

| ラウンド | 選べる行動 | 分かること |
| --- | --- | --- |
| 近づく記録 | 分母範囲へ投資、別の分数、相手の監査 | 有限の一例と、いくら先でも続く主張の違い |
| ゼロへの逃げ道 | 2×2数表、ゼロ・倍率・小ささの監査 | 対角の積の差、D倍すると差はD²倍、非零整数の大きさ |
| 混ぜ方 | 行を増やす、種類の配分、手計算の反例 | 一種類の対策だけでは混合配置が残る |
| 両立する配分 | 目盛りを細かくする、弱い条件の監査 | 入口2条件とδ調整後2条件を同時に守る |

公開は各1回。成立+6、監査成立+4、崩れた主張−3。正しい主張への監査は券だけ使います。両者成立時の比較+2は、順に「誤差×q²」「公開した整数由来の下限」「全配置の指数k」「**入口2条件の小さい方の余裕**」。最後は調整後も含む4条件全て正で成立します。数表は整数化からの保証1/D²までを採点し、実際の差を読むだけの強い下限は採点対象にしません。

遊んだ後の問い: 種類0の4枚なら次数0,1,2,3の合計は6。2種類へ2枚ずつ分けると、次数は0,1と0,1。種類の合計2＋次数の合計2=4です。「どの配置でも指数6以上」のどこが崩れたでしょう。これは実際の項が非零・大きいという証明ではありません。

## 実装と制約

既存暗号Battleに近い純粋なcoordination hooks、チーム別projection、公開台帳、実際のPortal componentを使います。Bun入口が同じreducerとcomponentを接続。SDKは型だけで、本体SDKへの実行依存はありません。型契約の参照元はTenkaCloud `05ffed84`です。

得点・券・手番・計算はサーバーが決めます。余計なフィールド・古い盤の操作・範囲外を拒否。応答が失われた場合、画面から同じ操作を再送でき、券や得点は二重に動きません。公開まで試行は相手に見えません。行枚数は試行時点を保存し、後の強化で過去の証拠を書き換えません。

`127.0.0.1`のみで待受し、Host/Originと本文サイズを確認します。ただし**席の認証はありません**。URLを変えればどちらも選べ、試合を作り直せます。信頼できる1台で使う練習用です。公式点・本体認証・永続化の証拠ではありません。状態はメモリ内で再起動すると消えます。作り直したら両タブを再読み込みしてください。終了はCtrl-C。資源はローカルCPU・メモリ・ディスクだけで、課金が続くクラウド資源はありません。

本体local hostは現状`ac26-crypto-battle`を直接指定しています。新Battle登録にはTenkaCloud側との連携変更が必要です。対応済みと誤認させないため`metadata.json`・架空のDocker verifier・AWS templateを置いていません。共通カタログ検査は既存カタログを検査し、この試作の実行対応を証明しません。

## 検証

```sh
make test typecheck reference-test
make browser-test
```

ブラウザ試験は`playwright-core`とインストール済みの対応Chromiumを使い、ダウンロードしません。必要なら`BROWSER_EXECUTABLE`へ実行ファイルを指定します。画像はgit対象外の`reports/browser/`へ出力し、`BROWSER_OUTPUT_DIR`で変更できます。

2つの独立ブラウザ席で画面だけを操作し、4ラウンド・8主張、公開前の非表示、再読み込み、受理後の応答喪失と同一再送、手計算の混合配置、精算・終了解説・スマホ幅を確認。別テストで分数演算、独立列挙、不正入力、同時書込み、監査再利用、券切れ、不変性、行枚数保存を検査します。独立数学レビューは丸め・負の整数・行列式・上限と実値の混同などの欠陥を発見し、修正しました。

Lean全依存ビルド・公理監査・Comparator、本体host登録、AWS実機、独立した人間による試遊は未実施です。有限のゲームで原稿の無限の定理を検証したとは扱いません。
