# セッション防衛戦 — ローカル2人対戦の試作

架空の広告管理室で、ログイン後の証拠を使う攻撃役と、限られた予算で守る防衛役を交代する。用意された演習用の証拠を試す → 架空の管理者・顧客リンク・広告予算の変化を見る → 対策を選ぶ → 同じ操作を再試験する、という4ラウンドのゲーム。実際の事件の侵入原因は未特定であり、その再現ではない。

**TenkaCloud本体への登録は未完了。** このPRは既存coordination hook形と実Portal slotを用いた試作を追加する。本体local hostの認証・SQLite復元・公式順位表まで通した意味ではない。[必要な本体登録変更](docs/INTEGRATION.ja.md)を参照。

## 起動

Bun 1.3.11を用意し、このディレクトリで実行する。

```sh
make install
make dev
```

ターミナルに出る **alpha / bravoの別々のURL** を2つの新規ブラウザ環境で開く。URL末尾の`#seat=dev_seat_…`はこの試作専用の席キー。実アカウントの資格情報を入力しない。両者が「準備完了」。攻撃役は「演習用の証拠を入力へコピー」して管理操作を1つ試し、「被害を確認した・防衛役へ」で渡す。防衛役が予算6以内で対策を選ぶ。再試験では攻撃役が操作し、防衛役は「正規の担当者で仕事を確認」する。

各段階は75秒。攻撃の試行券は対策前・再試験にそれぞれ4枚。攻撃点は再試験の被害、防衛点は`max(0, 100 − 被害 − 使用予算×3 − 正規の仕事が未確認なら20)`。前半2回は対策前の証拠、後半2回は対策後の新しい証拠も提供される。起動・待機・対策前の試行・無料の手がかりで加点されない。最後に両者の合計点とリプレイを比較する。

失効、15秒の期限、重要操作の追加本人確認、別担当者の承認、普段の役割の縮小を選べる。初回ログイン強化とHttpOnlyも模型として比較する。HttpOnlyはCookieをページのプログラムから読ませない設定であり、既に渡された証拠の再利用や端末侵害を一律に防ぐという意味ではない。予算はこのゲーム固有の運用負担の単位で、製品の費用や実被害額ではない。

`?lang=en#seat=…`で英語表示。サーバーは127.0.0.1:5666限定。別ポートは`PORT=5667 make dev`。停止はCtrl-C。再起動で試合・席キーは消える。AWS、Docker、課金資源、Region指定、外部送信は使わない。追加のクラウドteardownはない。

## 認証と模型の境界

演習用証拠は`lab_session_…`、席キーは`dev_seat_…`、操作限定許可は`lab_grant_…`。それぞれの用途を分離し、演習用証拠で席のAPIを認証できない。サーバーは試合秘密から証拠を生成し、session・owner・round・失効・期限・役割を照合する。許可はsession/action/round/期限/発行役に束縛され、成功時に一度だけ消費する。`verified=true`などのフラグは受け付けない。

パスキー、別端末での本人確認、承認担当者の独立ログインは**未実装の模型**。防衛役の専用席を本人の別経路に見立て、正規操作にだけ許可を発行する。承認の別principal（担当者の識別）はサーバー内で模型化する。「正規の仕事」の確認は予算変更を実行し、承認対策を選んだ場合は承認付き管理者追加も試す。普段の役割で禁止していれば承認があっても拒否する。実サービスでは別担当者の認証・承認対象の確認を別途実装する必要がある。両担当者の侵害や誤承認、操作中の端末乗っ取りはこの模型の保証範囲外。

実ブラウザprofile、実Cookie、OSの資格情報保管、Google/Microsoftの認証、本番アカウント、フィッシング、マルウェア、任意URL攻撃、OSネットワーク設定は扱わない。ページが読み書きするのはこの演習プロセスのダミーデータだけ。

## 検証

```sh
make test typecheck
make browser-test
# 本体hookとの互換性検証。準備済み本体checkoutを読み取るだけ。
TENKA_ROOT=/path/to/TenkaCloud bun tests/platform-smoke.ts
# カタログrootで
make install
make agent-gate
```

ブラウザ検証には専用のPlaywright Chromiumが必要。`bun node_modules/playwright-core/cli.js install chromium`で準備するか、`BROWSER=/path/to/dedicated/chromium make browser-test`を使う。新規の一時環境だけを作り、普段のprofileは読まない。ブラウザテストは画面の入力のみで対戦する。サーバー専用の状態・採点コードはブラウザbundleに含めない。
