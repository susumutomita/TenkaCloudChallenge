# Security boundary and independent review

This is a synthetic loopback-only educational lab. Its fixed operations mutate dummy state; neither the game nor its browser harness reads real profiles/cookies/credential stores, sends data to external services, accepts arbitrary targets, changes OS networking or implements credential theft. The supplied evidence intentionally models reuse after acquisition. It does not establish the cause of a real advertising incident.

Three independent capabilities are used: disposable harness seat keys, fictional application sessions, and private operation grants. The first maps requests to a trusted team. The second is deliberately shared with the attacker by the exercise. The third remains server-only, derived from per-match secret material and bound to session, action, round, issuer and expiry, then consumed on successful authorization. Identity/routing values are not used as secret seeds. Unknown fields, forged flags, oversized input, wrong roles and stale revisions are rejected. Public projections omit secret/session/grant/receipt storage and contain no victim grant. Replay and score reasons never include credentials or submitted proof values.

Passkeys and independent reviewer authentication are not implemented. The defender seat models an independent owner authenticator. A distinct server-side reviewer principal models approval for the legitimate admin test; this is not proof of a real approval system's assurance. The learner can observe positive approval, denial without approval, and role restriction winning over approval. Export is outside the declared approval/step-up policy. Mistaken approval, compromise of both principals and interactive access to an authenticated device require additional controls outside the model. HttpOnly and initial-login strength are comparison models, with their actual scope explained before selection.

Independent reviewer agent `/root/security_review` inspected code and ran its own tests, separate from the author's suite. It found a delayed configure-timeout path that omitted the late-leak fixture, allowing an expired baseline token to mask damage in later rounds. Both normal and timeout paths now use `startContest`; an independent regression confirmed the fix. It also identified the missing positive reviewer demonstration, stale GET rendering and same-instance match switching. Positive reviewed admin execution, monotone projection acceptance and a job/team-specific component key address these points.

The review found no remaining security blocker within this lab's scope. The independent suite checked host/origin/seat rejection, size bounds, forged grants, grant scoping/expiry/one-use, revocation, event separation, projection confidentiality, idempotency and settlement fairness. This is an independent agent review, not a GitHub approval or a human penetration test. See EVIDENCE.md for final test counts and limitations.

The host integration is unfinished. The local harness has in-memory state and disposable seat links; the person controlling that process can inspect all state. It is not a deployment authentication service. The eventual host must derive team/event identity from its established authentication and persist state plus score atomically.

Source checks (2026-10-07): session expiry, revocation and HttpOnly's scope follow [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Server-side, operation-specific authorization and enforcing it before execution follow [OWASP Transaction Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html). These support the general teaching model; they make no claim about the unestablished incident cause or any product's current policy.
