# 運営ガイド — 解答を含みます

## 60分の進行案

説明5分、調査・実証15分、修復25分、再起動と最終検証10分、振り返り5分。これは進行案であり、自動タイマーではありません。2〜4人のチームで、調査、バッチ読解、修復、記録を分担できます。問題ごとの固定担当にせず、途中で説明を交換してください。

事前に `./gameday.sh test` を実際の運営ホストで実行し、全テスト通過とCPU・メモリ余裕を確認します。初回のイメージビルドは開会前に済ませます。配布版の作成環境ではDockerそのもののビルド・起動を試せていないため、この事前試験を省略しないでください。

チームごとに `./gameday.sh start team1`、`team2` のように起動します。参加者へはそのコンテナのauditorシェルだけを渡し、Docker権限や運営ホストへの一般シェルは渡しません。遠隔シェルの認証・配布機構は別途必要です。フルアーカイブは運営向けで、参加者向け配布物ではありません。

調査終了前に `submit` を実行し、記録された得点をチームと確認してから `repair --yes` で確定します。採点は運営が実施します。編集を止めてもらい、`score`で再起動後の状態を検証します。すべてのチームで同じ回数や区切りの採点にしてください。

## 模範ルートのスモークテスト

次の手順は**解答を実行します**。練習用の新しいチームだけで実行してください。

```bash
./gameday.sh start rehearsal

docker exec -i --user 1100:1100 nightshift-rehearsal \
  /bin/bash -s < tests/reference-discover.sh

docker exec --user 0:0 nightshift-rehearsal \
  /bin/bash /opt/nightshift/control.sh live

./gameday.sh submit rehearsal
./gameday.sh repair rehearsal --yes

docker exec -i --user 1200:1400 nightshift-rehearsal \
  /bin/bash -s < tests/reference-repair.sh

./gameday.sh score rehearsal
./gameday.sh down rehearsal --yes
```

期待する最終結果は1,000点です。これは模範解答からの機能検証であり、初見参加者の可読性や60分での完走を証明するものではありません。

## 解答の要点

ミッション1では、バックアップの精算キーをauditorから読めることが問題です。所有者operator、グループworkloadという関係を維持し、batchがグループ権限で読める0640へ直します。削除や000では正当なバッチも読めず、修復点は付きません。

ミッション2では、バッチが名前だけで呼ぶ`render-receipt`を、PATHの先頭にある書き込み可能なvendorディレクトリで差し替えられます。実証はbatchだけが読めるトークンをbatchの証拠ディレクトリにコピーするだけです。外部通信や実在情報の窃取は行いません。修復では信頼できるPATHまたは絶対パスを使い、不要な書き込み権限と残されたコマンドも確認します。**ディレクトリだけを閉じても、既存のauditor所有ファイルが書き換え可能なら不十分**です。

ミッション3では起動時の互換設定スクリプトが、精算キーの権限とPATHを以前の状態へ戻します。起動設定も修復する必要があります。模範解答は該当スクリプトを`.disabled`へ移しますが、その中身を安全な設定へ修正しても構いません。採点は特定の修正文字列だけを見るのではなく、再起動後の読み取り権限・コマンド差し替え可能性・正当な処理を検証します。

## トラブル時

`doctor`失敗：Dockerが起動しているか、現在のDocker contextへ接続できるかを確認します。

同名のコンテナがある：既存の演習なら`status`を確認します。所有ラベル不一致は別のコンテナの可能性があるため、勝手に削除しないでください。

`.lock`が残った：対応する処理が本当に停止していることを確認します。PIDは`.state/<team>/.lock/pid`にあります。動作中の採点を止めずにロックだけ削除しないでください。プロセス停止を確認した場合のみ、そのチームの`.lock`を削除して再試行します。

採点が途中で失敗：新しい得点は記録しません。アプリや証拠ファイルの状態、容量、プロセス数を確認してください。強制停止が採点プローブの復元まで中断させた場合は、残った`.probe-*`ディレクトリからの復元を運営が確認するか、練習環境をリセットします。

Dockerコンテナ自体を停止した：tmpfs上の編集・証拠は永続化しません。通常の一時停止手段にはしないでください。ホスト状態だけが残っていても、古い得点を新しい環境へ流用せず`reset --yes`で作り直します。

## 振り返り

「どのユーザーの権限で実行されたか」「必要な読み取りだけをどう残したか」「実行時の設定と再起動時の設定は一致していたか」「なぜ単なる生存確認では不十分か」を、変更前後のログとともに説明してもらいます。

この初版は時点ごとの業務検証です。時間積分の稼働率得点、ネットワーク上の攻防、ホスト侵害競技、一般的な脆弱性検出器ではありません。
